# 範囲の決め方と対象の列挙（harness-audit）

手順 2 で監査の範囲を決めるとき、手順 3 で対象のファイルを列挙するときに読む。

## 範囲の種類

| 範囲 | 指定 | 対象 |
| --- | --- | --- |
| 全体 | 引数が空のとき、質問で選ぶ | 追跡中の全テキストファイル |
| 差分 | `--diff`、または質問で選ぶ | 今のブランチがマージ先から変えた、追跡中のテキストファイル |
| ディレクトリ | パス（空白区切り）、または質問で選ぶ | 指定したパスの下の、追跡中のテキストファイル |

- 引数が空なら、`AskUserQuestion` で 3 つから選んでもらう。最終チェックは全体を一度に見るのが目的のため、「全体」を先頭に置き、ラベルに「(Recommended)」を付ける
- 「ディレクトリ」が選ばれたら、先に下の「対象を列挙する」で全体の一覧を作る。上位のディレクトリごとの件数を選択肢に出し、選択肢に無いパスは自由記述（Other）で受ける
- `--diff` とパスが混ざっていたら、どちらの範囲にするかを質問で選び直してもらう。推測でどちらかに決めない

## 対象を列挙する

リポジトリのルートで、追跡中のテキストファイルを列挙する。範囲がディレクトリなら、`--` の後ろにそのパスを並べて絞る。

```bash
git grep -I -z --name-only -e '' -- <範囲のパス（無ければ省く）> \
  | tr '\0' '\n' \
  | grep -vE '(^|/)(node_modules|vendor|dist|build|tmp)/' \
  | grep -viE '\.(svg|map)$|\.min\.(js|css)$|(^|/)(package-lock\.json|pnpm-lock\.yaml|[^/]*\.lock)$'
```

- テキストかどうかは、拡張子ではなく中身で決める（`-I` はバイナリのファイルを飛ばす）。画像・Excel などを、拡張子の一覧に頼らずに除くため。中身が空のファイルも出ない
- `-z` を付けて、日本語などのファイル名をそのまま出す。付けないと、`"\350\250\255..."` のような記号付きの形になり、後の段で開けないため
- 依存・生成物・`tmp/`・圧縮済みのファイル・lock ファイルも除く。人が書いたテキストではなく、規約を当てても意味が無いため
- 一覧の各ファイルの大きさ（バイト）を `wc -c` で取る。Workflow が、小さいファイルを束ねるのに使う
- 0 件なら、その旨を伝えて終わる
- 範囲が差分かディレクトリのときは、注記に使う全体の件数を数えるため、パスを付けない同じコマンドも 1 回実行する

## 差分の対象を決める

1. マージ先を決める。`base-branch.md`（`SKILL.md` の「参照ファイル」の表にあるパス）の「規約を探す」「今のブランチのマージ先を決める」「比べる先を最新にする」に従う。PR も規約も無ければ、既定ブランチ（`origin/HEAD`）と比べる
1. `git branch --show-current` が比べる先と同じなら、差分は無い。`errors.md` の「差分が使えないとき」に従う
1. 変えたファイルを取る。`docs-sync` と同じく、マージ先との分岐点と今の作業ツリーを比べるため、未コミットの追跡中の変更も入る。未追跡の新規ファイルは入らないため、見たいときは先に `git add` する

   ```bash
   git merge-base HEAD <比べる先>
   git diff --name-only --diff-filter=d -z <merge-base のハッシュ>
   ```

1. 全体の一覧にもあるものだけを残す。消したファイルと、バイナリ・依存・生成物は、ここで落ちる
1. 0 件なら、その旨を伝えて終わる

## 控えるもの

- 手順 6 の `scope`：範囲の種類（`all`・`diff`・`dir`）、差分なら比べた先、ディレクトリならパス、全体の件数
- 差分なら、比べた先の根拠（PR のマージ先・規約のファイル・既定ブランチ）と、`git fetch` を断られたときはそのこと。手順 7 の報告に書く

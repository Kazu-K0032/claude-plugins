# 検証コメント出力テンプレート

`pr-create` Skill が `tmp/<ブランチ名>/pr-verify_<yyyymmdd_hhmmss>.md` に書き出す、レビュワー向け検証コメントの出力形式を定義する。

## テンプレート

以下のテンプレートに沿うこと。それ以外の項目を勝手に追加しないこと。

```md
## 前提条件

- xxxxされていること

## チェック項目

### 〇〇について

- [ ] xxxxしたとき、xxxxになるか
- [ ] xxxxしたとき、xxxxになるか

### 〇〇について

- [ ] xxxxしたとき、xxxxになるか
- [ ] xxxxしたとき、xxxxになるか
```

## 前提条件の書き方

チェック項目を試す前に必要な、**このブランチ特有の準備**だけを書く。

- ブランチの切り替え・`git pull`・開発環境の起動・管理画面へのログインといった大前提は書かない
- 差分の内容から必要な準備を判断する

  | 差分に含まれるもの | 前提条件に書くこと |
  | --- | --- |
  | スキーマ・フィールド定義の追加・変更 | 定義を取り込み済みであること（インポート・マイグレーション適用） |
  | 初期データ・シードデータ | データを再投入していること |
  | フロントのアセット（CSS / JS のソース） | ビルドを実行し、成果物が更新されていること |
  | ルーティング・URL 構造 | ルートのキャッシュ再生成を実行していること |
  | 依存パッケージの追加・更新 | パッケージのインストールを実行していること |
  | プラグイン・拡張の設定に依存する機能 | 対象を有効化し、設定を入れていること |

- 準備が要らないときは `- なし` と 1 行書く

## チェック項目の書き方

- **マージ前にレビュワーが自分で確かめられることだけを書く**。マージ後にしか分からないこと（デプロイの発火、サーバー上のファイル状態、スケジュール実行の結果）は項目にしない
- **CI の必須ジョブが検証する範囲は書かない**。PR で自動的に落ちるため、レビュワーがやる意味がない
  - 書かない: Lint / 静的解析 / 自動テストのスペックが見ている挙動 / テスト前に走る前処理 / 秘匿情報の混入
  - 書く: CI がカバーしないもの。本番相当の依存が要る管理画面の挙動・特定環境でしか動かない JS・ドキュメントのリンク切れ
- 項目は「〇〇したとき、〇〇になるか」の疑問形で書く。レビュワーが Yes / No を判定できる粒度にする
- 粒度は簡易でよい。次のような手を動かせば分かるレベルに寄せる
  - `〇〇コマンドを実行したとき、エラーが出ないか`
  - `管理画面で〇〇を作るとき、〇〇というバリデーションがかかるか`
  - `ローカルで〇〇のページを開いたとき、〇〇が表示されるか`
- 見出しは変更のまとまり（機能・ワークフロー・ファイル群）ごとに分ける
- チェックボックスは**空欄のまま出力する**（埋めるのはレビュワー）

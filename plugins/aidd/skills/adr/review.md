# ADR のレビューチェックリスト

ADR を作成・更新したあとに、確かめる項目を示す。`SKILL.md` の手順 5 で読む。

## 更新時のチェック

- **ADR の不変性**: 初回作成後の ADR の変更は、`SKILL.md` の禁止事項（本文の変更）に従う
- ステータス変更: フロントマター `status` を更新し、一覧の状態の列も合わせる
- 決定を覆す場合: `SKILL.md` の手順 4 に従う

## レビューチェックリスト

作成・更新後に以下を確認する。

- [ ] ファイル名が判断の対象名になっている（ツール名・結論を使わない。例は `adr-format.md` の「ファイル命名」の表）
- [ ] 題（見出し）だけで、何を決めたかが分かる
- [ ] 決めたことと理由が書いてある
- [ ] 「判断の種類」が 1 つに絞られている
- [ ] 既存の判断の変更なら、旧 ADR へのリンクがあり、旧 ADR の `status` が新 ADR にリンクしている
- [ ] 状態が `承認済み` か、空けた所があれば `提案中` になっている
- [ ] 一覧に行があり、題・状態が ADR とそろっている
- [ ] 関連 ADR のリンク切れがない（未作成なら「（予定）」付き）
- [ ] 決定・理由・却下理由がエンジニア歴 1 年目でも読める平易さで書かれている
- [ ] バージョン指定がある場合、その理由が書かれている
- [ ] 型の目安（`adr-format.md` の「型」の表）に収まっている。収まらないなら重い型に切り替える

詳細版で、該当の節を書いた場合のみ：

- [ ] 意思決定の要因に前提条件が混入していない
- [ ] 決定の根拠が意思決定の要因ごとに書かれている
- [ ] 参考資料が「なし」または一次情報 URL で埋まっている（空欄 NG）
- [ ] 「検討した選択肢」のうち公式ページがある候補（ツール・ライブラリ・サービス）に公式リンクが付与されている
- [ ] 使用する参考資料は評価の高い日本語記事を優先。英文の公式ドキュメントの方が信頼性が高ければそちらを優先している
- [ ] 参考資料の各リンクに `— {タグ}: {1 行根拠}` 形式で信頼性根拠が付与されている

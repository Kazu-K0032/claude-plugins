# 既存の ADR の状態を変える（adr）

既存の ADR を廃止するとき、別の ADR で判断を置き換えるときに読む。どちらも、手順 1 で利用者に選んでもらってから行う。既存の ADR の状態を変えるのは、利用者が選んだときだけ。

## 守ること

- 初回作成後の ADR は、フロントマター以外を変えない（ADR の不変性）。ただし、`提案中` で空けた所を人が埋めるのはよい
- 状態を変えたら、フロントマターの `status` を直し、一覧の状態の列も合わせる

## 廃止する

決定が不要になったときは、フロントマターの `status` を `廃止` にし、一覧の状態の列も合わせる。

## 判断を変える（置き換える）

リリース後の問題や状況の変化で、既存の ADR の判断を変えるときの手順。旧 ADR の本文は書き換えず、新しい ADR を足して履歴として残す。

1. 置き換える旧 ADR を Read し、何を決めていたかを確かめる
1. `SKILL.md` の手順 2〜4 に従って、新しい ADR を作る
   - ファイル名は、旧 ADR と同じ判断の対象名にする（例：旧 `2026-04-10-session-storage.md` → 新 `2026-09-30-session-storage.md`）
   - 判断の種類は「既存の判断の変更」にし、背景に元の判断と、変える必要が出た経緯を書く
   - 置き換える旧 ADR への相対リンクを書く（詳細版は「関連情報」の「置き換える ADR」）。きっかけになった障害報告・作業ログ・Issue があれば、「経緯の記録」にリンクする
1. 旧 ADR の `status` を `[YYYY-MM-DD-subject](YYYY-MM-DD-subject.md) により置き換え済み` に変える（新しい ADR への相対パスのリンクを必ず含める）。本文への追記は一切しない
1. 一覧に新しい ADR の行を足し、旧 ADR の状態の列も合わせる
1. 新しい ADR と、状態を変えた旧 ADR を、`writing-guide.md` の「レビューチェックリスト」で確かめる

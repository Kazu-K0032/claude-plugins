# `--issue-only` のときの進め方（issue-start）

`--issue-only` が付いたときに読む。ブランチを作らず、実装もせず、Issue の記述の確認と要件の詰めのあと、本文の更新だけで終わる。本文を詳しく書き直したいだけの場面で、着手の手順全体を走らせないため。

## 手順の通し方

| 手順 | `--issue-only` のとき |
| --- | --- |
| 1〜3 | 通す。手順 3 は、Issue が閉じていても止めない。本文の更新は着手ではなく、閉じた Issue の記録を詳しく直す場面があるため。「直す対象がもう実装されている」でも止めない。止める基準のうち、引用が引用元に無いときと、規約に合わないときは、今までどおり止める |
| 4〜6 | 飛ばす。ブランチも担当者も触らない |
| 7 | 通す。確認の結果を示して、計画モードに入る。承認の前に Issue を書き換えないため |
| 8 | 通す。補足は計画に入れ、承認の画面で、どう読んだかを示す（P11）。記述と今のコードの食い違いは、本文に直す点に含めず、報告に書くだけにする。頼まれたのは本文の詳細化で、Issue の意図を勝手に書き換えないため。あわせて、下の「bot に頼まない Issue の注記」で、bot の範囲を超えるかを判定する |
| 9 | 通す。`issue-update.md` の手順で書き換える。既存のタスクのチェックの状態は変えない。実装をしないため。手順 8 で bot の範囲を超えると判定したら、本文の冒頭に注記を置く |
| 10〜16 | 飛ばす。実装・検査・文書の点検・ADR の質問・ステージ・コミットメッセージ・PR の下書きは行わない |
| 17 | 通す。`result-template.md` の形のうち、行った節だけを書く |

## 計画に書くこと

- Issue の種類と、詳しく書く節（`short-body.md` の「Issue の種類ごとの書き分け」）。補足があれば、どう読んだか（例：「再現手順を詳しく」なら、再現手順の節を詳しくする）
- 本文をどう書き換えるか。概要が 300 文字を超えるなら、どこを縮めるか

## 補足が種類の書き分けと食い違うとき

補足が `short-body.md` の種類ごとの書き分けや概要の上限と食い違うときは、手順 8 の問いで、そのとおりにはできないと伝える。続けて、「決まりどおりに書く」か「止める」かを `AskUserQuestion` で聞く。「決まりどおりに書く」を推奨にする。手順でできない補足を推測で進めないため（P11）。

- 例：文書・版の更新の Issue に「詳しく」と頼まれたとき。この種類は、概要とタスクだけにする決まりで、詳しく書いても読む負担が増えるだけのため
- 例：概要を 300 文字より長くしたいと頼まれたとき。概要の上限は、補足があっても変えない
- 食い違わない補足（バグ修正に「再現手順を詳しく」など）は、そのまま計画に入れる

## bot に頼まない Issue の注記

Issue を読んで実装する bot（GitHub Actions の Claude など）があるリポジトリでは、bot が変えられないファイルを主に変える Issue に、人が対応すると冒頭に書く。頼まれた bot が実装しきれず、Issue のとおりでない PR ができるのを防ぐため。

### 手順 8 で判定する

1. リポジトリの決まり（`CONTRIBUTING.md` の bot の節、`docs/` の bot の文書など）を探す。bot に変えさせないファイルや、頼まない Issue の決まりがあれば、それに従って判定する（P6 の「同梱の決まりは既定」）
1. 決まりが無ければ、`.github/workflows/` を `anthropics/claude-code-action` で Grep し、bot があるかだけを見る。bot が無ければ、注記は書かない
1. bot はあるが決まりが無ければ、範囲を超えるかを手順 8 の問いで利用者に聞く。推測で決めないため

### 手順 9 で書く

範囲を超えるなら、本文の冒頭（概要の前）に次の形の注記を置く。`> [!IMPORTANT]` の次の行は、`> この Issue は bot に頼まず、人が対応する。` で始め、この文言は変えない。bot の側が、行頭のこの文言で見分けるため。続けて理由を 1〜2 行で書く。既に注記があれば、そのまま残す。

```markdown
> [!IMPORTANT]
> この Issue は bot に頼まず、人が対応する。`.github/workflows/` の変更が主で、bot に変えさせないファイルにあたるため。
```

範囲を超えないと判定したら、注記は書かない。既にある注記は消さない。人が置いた判断を、勝手に覆さないため。

## 書き込むもの

- GitHub：本文の更新だけ（手順 9）。担当者・ブランチ・既存のコメント・ラベルは変えない。手順 3 で止めたときのコメントは、選ばれたときだけ今までどおり
- `tmp/<ブランチ名>/issue-start/`：書き換える前の本文（`<ts>_issue_before.md`）と、反映する本文（`<ts>_issue.md`）。`<ブランチ名>` は、`git branch --show-current` で取る今いるブランチ。`issues/` などの形でなくてもよい

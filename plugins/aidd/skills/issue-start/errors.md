# 止めるとき・止められたとき（issue-start）

手順 1 で Issue を取れない・リポジトリが違うとき、手順 3 で「前提が崩れている」と判定したとき、GitHub への書き込みが止められた・失敗したときに読む。

## 中断するとき

- `gh issue view` が失敗したら、その時点で中断して原因を報告する（存在しない・権限が無い・リポジトリが違う）
- Issue の URL のリポジトリが、今いるリポジトリ（`gh repo view` の `nameWithOwner`）と違う場合は中断する。ブランチを作っても、ここでは移動できないため

## 前提が崩れているとき

ブランチを作らずに止める。

1. `result-template.md` の形のうち「判定」と「確認の結果」の節で確認の結果を示し、止めた理由と、Issue をどう直せば着手できるかを書く
1. `AskUserQuestion` で、Issue にコメントするかを聞く。Issue が閉じているときは、聞かずに終わる。閉じた Issue に理由を残しても、読む人がいないため

| 選択肢 | 次の動き |
| --- | --- |
| コメントせずに終わる | そのまま終わる |
| Issue にコメントして終わる | `comment-template.md` の形で本文を作り、数えてから下のコマンドで投稿して、結果を 1 行で伝えて終わる |

### コメントの数え方と投稿

本文は、投稿する前に標準入力から数える。超えていたら縮め、もう一度数える。

```bash
node <body_length.js のパス> - <<'__ISSUE_BODY__'
<テンプレートで作った本文>
__ISSUE_BODY__
```

`<body_length.js のパス>` は、`SKILL.md` の「参照ファイル」の表にあるパスにする。場所を表す変数は `SKILL.md` の中でしか置き換わらないため、この文書では使わない。

上限に収まった（終了コードが 0 の）ときだけ、次のコマンドで投稿する。数えるコマンドと同じ呼び出しで続けて実行しない。超えたまま投稿しないため。

- 3 回直しても収まらないとき：超えた箇所を示し、そのまま投稿するかを `AskUserQuestion` で聞く
- Node.js が無い・実行を断られたとき：数えずに投稿し、そのことを伝える

```bash
gh issue comment <番号> --body-file - <<'__ISSUE_BODY__'
<テンプレートで作った本文>
__ISSUE_BODY__
```

表やバッククォートを含む本文を `--body` の引数に入れると、シェルのクォートで崩れやすいため、標準入力から渡す。

## 書き込みを止められた・失敗したとき

| 書き込み | 止められた・失敗したときの動き |
| --- | --- |
| ブランチの作成（手順 5） | 失敗したら（同じ名前のブランチが既にある・書き込み権限が無い等）、エラーを報告して終わる |
| 自分を担当者に足す（手順 6） | フックなどで止められたら、そのまま進み、担当者を手で足すよう報告に書く |
| Issue の本文の更新（手順 9・13） | 止められたら（許可を断られた・フックで止められた）、本文は `tmp/` に残したまま先へ進み、報告に理由と、手で反映する方法を書く |
| コメント（手順 3） | 投稿できなかったら（許可を断られた・権限が無い・フックで止められた）、理由を伝えて終わる |

# 着手を止めるとき

`issue-start` で、前提が崩れているときと、作業ツリーに未コミットの変更があるときに、先へ進む前に止めて扱いを決める手順。

## 前提が崩れているとき（手順 3）

手順 16 の形のうち「判定」と「確認の結果」の節で確認結果を示し、止めた理由と、Issue をどう直せば着手できるかを書く。そのうえで `AskUserQuestion` で Issue にコメントするかを聞く。Issue が閉じているときは聞かずに終わる。閉じた Issue に理由を残しても、読む人がいないため。

| 選択肢 | 次の動き |
| --- | --- |
| コメントせずに終わる | そのまま終わる |
| Issue にコメントして終わる | `comment-template.md` の形で本文を作り、数えてから下のコマンドで投稿して、結果を伝えて終わる |

本文は、投稿する前に標準入力から数える。超えていたら縮め、もう一度数える。

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/body_length.js" - <<'__ISSUE_BODY__'
<テンプレートで作った本文>
__ISSUE_BODY__
```

上限に収まった（終了コードが 0 の）ときだけ、次のコマンドで投稿する。数えるコマンドと同じ呼び出しで続けて実行しない。超えたまま投稿しないため。

- 3 回直しても収まらないとき：超えた箇所を示し、そのまま投稿するかを `AskUserQuestion` で聞く
- Node.js が無い・実行を断られたとき：数えずに投稿し、そのことを伝える

```bash
gh issue comment <番号> --body-file - <<'__ISSUE_BODY__'
<テンプレートで作った本文>
__ISSUE_BODY__
```

表やバッククォートを含む本文を `--body` の引数に入れると、シェルのクォートで崩れやすいため、標準入力から渡す。投稿できなかったら（許可を断られた・権限が無い・フックで止められた）、理由を伝えて終わる。

## 作業ツリーに未コミットの変更があるとき（手順 4）

手順 1 の `git status --porcelain` に出力があれば、ブランチを作る前に止め、`AskUserQuestion` で扱いを聞く。ブランチを移ると、未コミットの変更が新しいブランチへ持ち越されるため。

| 選択肢 | 次の動き |
| --- | --- |
| 中止する | ユーザーが変更を退避・コミットしてから、もう一度呼ぶよう案内して終わる |
| このまま移動する | 変更を持ったまま手順 5 へ進む。持ち越した変更は、手順 14 でステージに置かない |

# Issue へのコメントのテンプレート

`issue-start` が、ユーザーが選んだときだけ Issue に投稿するコメントの形を決める。形を変えたいときは、このファイルを直す。

## 書き方

- 一文を短くし、1 項目は 1〜2 文に収める。確かめた経緯は書かず、結論と確かめた先（`<ファイル>:<行>` や URL）だけを書く
- 中身が無い節は見出しごと消す。テンプレートに無い節は足さない
- 報告にある「合っていたこと」と「ブランチ」の節は載せない。Issue を読む人が次に動くのに要らないため

## 着手前の確認

判定が「漏れ・食い違いがある」で、ユーザーが「Issue にコメントしてから進める」を選んだときに使う。決めることは 1 件ごとに見出しにし、その下に推奨案と理由を書く。

```markdown
## 着手前の確認

`/aidd:issue-start` で、Issue の記述を今のコードと突き合わせた結果。

### チェックリストに無い修正箇所

- `<ファイル>:<行>` <直す理由>

### 食い違い・注意点

- <記述と今のコードの違い・未確認の引用など>

### <決めること>

推奨：<推奨案>。<理由>
```

## 着手を見送った理由

判定が「前提が崩れている」で、ユーザーが「Issue にコメントして終わる」を選んだときに使う。

```markdown
## 着手を見送った理由

`/aidd:issue-start` で、Issue の記述を今のコードと突き合わせたところ、前提が崩れていた。

- <当たった止める基準と、確かめた先>

### 着手するには

- <Issue をどう直せば着手できるか>
```

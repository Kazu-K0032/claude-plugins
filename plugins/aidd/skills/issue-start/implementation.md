# 実装と検査（issue-start）

手順 10 で実装するとき、手順 11 で検査するとき、手順 12・15 でステージに置くとき、手順 16 で PR の下書きに使う差分を決めるときに読む。

## 実装する

- 計画どおりに直す。リポジトリの `CLAUDE.md`・`.claude/rules/` に従う
- 直した・作ったファイルを控える。手順 12・15 でステージに置くため
- 作業用の一時ファイル（スクリプト・中間ファイル・確認用の画像）は `tmp/<ブランチ名>/work/<目的>/` に置く。`<目的>` は、作業の中身が分かる英語の短い名前にする（例：`merge-conflict`）。消さずに済むようにし、スキルの出力と分けるため
- Python のスクリプトは `python -B` で実行する。`__pycache__` が `tmp/` に残ると、消せないファイルが増えるため
- ファイルを消す必要があるときは、消さずに、消すコマンドを報告に書いて人に頼む
- 途中で計画に無い判断が要るときは、`AskUserQuestion` で聞く

## 検査する

- テスト・Lint・型検査のコマンドを、`CLAUDE.md`・README・`package.json` の `scripts`・`Makefile`・`.github/workflows/` から探して実行する
- 失敗したら直して、もう一度実行する。直せないものは報告に書く
- コマンドが見つからなければ実行せず、報告に書く

## ステージに置く

- 控えたファイルだけを `git add <ファイル>` で置く。`git add -A`・`git add .` は、作業中にできたファイル（キャッシュなど）や手順 4 で持ち越した変更が混ざるため使わない
- 手順 12 で置いたファイルを、手順 15 でもう一度置いてよい。点検の後に直した分も入れるため

## 下書きに使う差分

手順 16 では、まだコミットが無い。そのため、コミットの一覧と差分（`git log`・`git diff <起点のブランチ>...HEAD`）の代わりに、ステージ済みの差分（`git diff --cached`）と `tmp.md` のメッセージを使う。前からのコミットがあれば、それも合わせて使う。

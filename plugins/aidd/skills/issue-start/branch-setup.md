# ブランチの用意（issue-start）

手順 4 で作業ツリーに未コミットの変更があったとき、手順 5 でブランチを用意するときに読む。

## 未コミットの変更があるとき

手順 1 の `git status --porcelain` に出力があれば、ブランチを作る前に止め、`AskUserQuestion` で扱いを聞く。ブランチを移ると、未コミットの変更が新しいブランチへ持ち越されるため。

| 選択肢 | 次の動き |
| --- | --- |
| 中止する | ユーザーが変更を退避・コミットしてから、もう一度呼ぶよう案内して終わる |
| このまま移動する | 変更を持ったまま手順 5 へ進む。持ち越した変更は、手順 12・15 でステージに置かない |

## 紐づいたブランチがあるとき

手順 1 の `gh issue develop --list` に紐づいたブランチがあれば、それぞれがマージ済みかを PR の状態で確かめる。マージ済みのブランチへ移ると、起点より遅れた所で作業を始めてしまうため。

```bash
gh pr list --head <ブランチ名> --state all --json number,state,url
```

- マージ済み：`MERGED` の PR があり、`OPEN` の PR が無い
- マージ前：それ以外（PR が無い・開いた PR がある）。コマンドが失敗したときも、マージ前として扱う

| 紐づいたブランチ | 次の動き |
| --- | --- |
| マージ前のものがある | 1 つでも、マージ前のブランチと「新しいブランチを作る」から `AskUserQuestion` で選んでもらう。1 つの Issue を複数の PR に分けて進めると、ブランチが複数紐づき、次の作業は新しいブランチで始めるため。ブランチは 3 つまで並べ、それ以上は自由記述で受ける |
| 全てマージ済み | 聞かずに、下の「ブランチを作るとき」の手順で新しく作る。外したブランチと PR は、報告の「ブランチ」に書く |

移動を選ばれたら、次のコマンドで移動する。

```bash
git fetch
git switch <ブランチ名>
```

## ブランチを作るとき

紐づいたブランチが無いとき、上で新しく作ると決まったときは、ブランチ名を決めてから作る。名前は規約に従い、規約が無ければ `issues/<番号>-<説明>` にする。説明は、Issue の要点を英語 2〜4 語の小文字・ハイフン区切りで書く（例: `issues/5-argument-hint`）。紐づいたブランチが既にあるときは、説明を今回の作業の要点にし、それらと同じ名前にしない。

### 起点に push していないコミットを確かめる

作る前に、起点のブランチに push していないコミットが無いかを確かめる。`--base` はリモートにある起点のブランチから作るため、手元にしかないコミットは入らない。紐づいたブランチへ移動するときは確かめない。起点のブランチから新しく作らないため。

```bash
git branch --list <起点のブランチ>
git fetch origin <起点のブランチ>
git log --oneline origin/<起点のブランチ>..<起点のブランチ>
```

- `git branch --list` に出力が無ければ、手元に起点のブランチが無い。確かめずに作る
- `git fetch` を断られたら、手元にある `origin/<起点のブランチ>` と比べる
- `origin/<起点のブランチ>` が無く `git log` が失敗したら、確かめずに作る

`git log` に出力があれば、ブランチを作る前に止め、出たコミットを示して `AskUserQuestion` で扱いを聞く。「中止する」を先頭に置き、ラベルに「(Recommended)」を付ける。含めずに作ると、手元で済ませた変更が新しいブランチに入らないため。

| 選択肢 | 次の動き |
| --- | --- |
| 中止する（push してから呼び直す） | ユーザーが起点のブランチを push してから、もう一度呼ぶよう案内して終わる |
| 含めずに作る | 下のコマンドでブランチを作る。含めなかったコミットは、報告の「残っていること・未確認」に書く |

出力が無ければ、そのまま作る。

### 作る

```bash
gh issue develop <番号> --name <ブランチ名> --base <起点のブランチ> --checkout
```

- 起点のブランチは、規約か `defaultBranchRef` から決め、`main` などに決め打ちしない
- `--base` は、リモートにある起点のブランチの最新から作る。手元の起点のブランチが遅れていても、先に最新にしなくてよい。進んでいるときは、上の確認で扱いを聞く

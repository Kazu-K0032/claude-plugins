# Issue の本文の更新（issue-start）

手順 9 で決めた仕様を Issue に反映するとき、手順 13 で Issue のタスクを更新するときに読む。どちらも同じ手順で書き換える。

1. 今の本文を `tmp/<ブランチ名>/issue-start/<ts>_issue_before.md` に書き出す
1. 書き換えた本文を `tmp/<ブランチ名>/issue-start/<ts>_issue.md` に作る。長さは `short-body.md` に従い、本文全体を 500 文字以内にする
   - 手順 9：「決めること」の節は、答えを書いた「決めたこと」にする。タスクは、決めた内容に合わせて足す・書き換える。チェックリストに無い修正箇所も、タスクに足す
   - 手順 13：実装で埋まったタスクにチェックを入れる。埋まっていないタスクは、外したままにする
   - 手順 13：ADR の検討の項目（例：「ADR の起票が必要か検討した」）があれば、チェックを入れる。手順 12 で候補が無く、聞かなかったときも入れる。候補が無いと判断したことも、検討にあたるため
1. 数える。超えていたら縮めて作り直し、もう一度数える。3 回直しても収まらなければ、超えた箇所を報告に書いて反映する。Node.js が無い・実行を断られたときは、数えずに反映し、報告に書く

   ```bash
   node <body_length.js のパス> tmp/<ブランチ名>/issue-start/<ts>_issue.md
   ```

   `<body_length.js のパス>` は、`SKILL.md` の「参照ファイル」の表にあるパスにする。場所を表す変数は `SKILL.md` の中でしか置き換わらないため、この文書では使わない。

1. 反映する

   ```bash
   gh issue edit <番号> --body-file tmp/<ブランチ名>/issue-start/<ts>_issue.md
   ```

反映を止められたときは、`errors.md` の「書き込みを止められた・失敗したとき」に従う。

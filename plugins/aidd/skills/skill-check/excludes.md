# 除外判定リスト

`skill-check` の判定で WARN/FAIL として検出されても、レポートから**除外**する項目を宣言する仕組み。

意図的に規約から外している箇所を毎回指摘されないようにするために使う。

## 探索先

除外リストは**プロジェクト側**に置く。プラグイン内のファイルはインストール時にキャッシュへコピーされるため、利用者が書き換えられない。

`skill-check` は次の順で探し、最初に見つかったものを使う。

1. `.claude/skill-check-excludes.md`
2. `.claude/skills/skill-check/excludes.md`（ローカル版 `skill-check` から移行したリポジトリ向け）

どちらも無ければ「除外なし」として判定を進める。**除外リストが無いこと自体は指摘の対象にしない。**

## 書式

```markdown
## <skill-name>

- **<該当する判定の見出し>**（<分類タグ>）
  - 理由: <なぜ除外するか>
  - 適用範囲: 永続 / 期限付き（YYYY-MM-DD まで）
```

`<分類タグ>` は `output-template.md` の「分類タグ」と同じ語彙を使う。

## 記入例

```markdown
## adr

- **`disable-model-invocation: false`**（フロントマター）
  - 理由: ファイル作成スキルだが、本文に「作成前の承認（必須）」の承認ゲートがある。Claude が自動発火してもユーザー確認を求めるため実害が低い。`false` のままにすることを意図的に選択
  - 適用範囲: 永続

## commit

- **`argument-hint` 未設定**（フロントマター）
  - 理由: `$ARGUMENTS` は本文末尾のオプション補足用で、固定的なヒント文言を置く意味がない
  - 適用範囲: 永続
```

## 運用

- 期限付きの除外は、期限を過ぎたら `skill-check` が「除外期限切れ」として報告に含める
- 除外は「規約違反を隠す」ためではなく「意図的な逸脱を記録する」ために使う。理由を必ず書く

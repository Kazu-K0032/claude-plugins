# Skill 点検レポート テンプレート

`skill-check` 実行時に `tmp/<ブランチ名>/skill-check_<yyyymmdd_hhmmss>.md` へ書き出す出力形式。**問題のある Skill は詳細を、問題のない Skill は 1 行で済ませる**。

````markdown
# Skill 点検結果

> （context7 等の参照が失敗した場合はここに警告文を 1 行で記載）

## サマリ

- 対象 Skill 数: N
- 総合判定: PASS | FAIL | 要相談
- FAIL 件数: N
- WARN 件数: N
- 要相談（スコープ）: N
- 除外リスト: `<見つかったパス>` | なし

内訳:

| Skill | 判定 |
| --- | --- |
| <name-a> | PASS |
| <name-b> | WARN |
| <name-c> | FAIL |

---

## <問題のない skill 名>

✅ 確認済み、問題なし（行数 N 行）

---

## <問題のある skill 名>

判定: WARN | FAIL | 要相談

- パス: `<SKILL.md への相対パス>`
- 行数: N 行
- description（原文）: `<原文>`

**問題点**:

- **<分類タグ>**: `<具体的な指摘>`
  - 該当箇所: `<file>:<line>` または `<セクション名>`
  - 改善提案: `<何を / どこに / どう変えるか>`
  - 変更影響: `<起動契機の変化など>`（description 改善時のみ）

（問題点ごとに上記ブロックを繰り返し）

**スコープ相談点**（該当する場合のみ記載、なければ省略）:

- 論点: `<相談内容>`
  - 選択肢 A: `<案 A の内容と影響>`
  - 選択肢 B: `<案 B の内容と影響>`
  - 推奨: A / B（理由）

---

（以降、Skill ごとに繰り返し）

## 推奨アクション

1. <優先度の高い順に対応すべき項目>
````

## 分類タグ

「問題点」の `<分類タグ>` には次のいずれかを使う。

| タグ | 意味 |
| --- | --- |
| フロントマター | `name` / `description` / `allowed-tools` / `argument-hint` 等の不備 |
| スコープ | 逸脱 / 不足 / 単一目的違反 / 境界明示不足 |
| 手順・参照 | 内部矛盾 / 出力先と権限の不一致 / 参照切れ / 多階層参照 |
| 本文 | 行数超過 / 用語揺れ / 時間依存表現 / スクリプト言語の選定ミス |
| SKILL.md 不在 | ディレクトリは存在するが SKILL.md がない（FAIL 確定） |
| 除外期限切れ | 除外リストの期限付きエントリが期限を過ぎている |

## 出力例（参考）

````markdown
## adr

✅ 確認済み、問題なし（行数 108 行）

---

## commit

判定: WARN

- パス: `.claude/skills/commit/SKILL.md`
- 行数: 43 行
- description（原文）: `ステージング済みの差分を分析し、Conventional Commits 形式のコミットメッセージを提案する。...`

**問題点**:

- **フロントマター**: 本文末尾の `$ARGUMENTS` に対する `argument-hint` が未設定
  - 該当箇所: フロントマター（5 行目周辺）
  - 改善提案: `argument-hint: "[補足指示（省略可）]"` を追加
````

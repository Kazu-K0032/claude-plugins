# 走査するログの決め方（ai-report）

手順 3 で、`collect` の出力の「走査対象ログ（カバレッジ）」を確かめるときに読む。

## 走査の対象

- 走査の対象は、cwd のログディレクトリだけではなく、同じリポジトリの全クローン・worktree の分を束ねる。クローンを分けて作業していると、cwd の分だけでは大半を取りこぼすため
- 判定は、各ログディレクトリのレコードに含まれる元の `cwd` を読み、その `cwd` の `git remote origin` が今のリポジトリと一致するかで行う。ディレクトリ名は `/` → `-` の非可逆なエンコードでパスを戻せないが、レコード自体が `cwd` を絶対パスで持っているため
- `cwd` が既に消えている・git の管理外で照合できない場合だけ、ディレクトリ名の前方一致で推定する。この推定はディレクトリ名の規約に頼るため、外れることがある
- 集計は、メインのセッションに加え、サブエージェント・Workflow の実行分（`<sessionId>/subagents/**` のログ）も含む。実費・実績を出すため

## 確かめ方

走査したディレクトリと判定の根拠は、`collect` の出力の冒頭と、レポートの「走査対象ログ（カバレッジ）」に出る。意図した作業ディレクトリが含まれているかを必ず確かめる。

意図した作業ディレクトリが抜けている、または無関係なリポジトリが混ざっている場合は、`--project-dirs` で対象を明示して `collect` をやり直す（ディレクトリ名でも絶対パスでも可）。

```bash
python3 -B "${CLAUDE_PLUGIN_ROOT}/skills/ai-report/scripts/analyze.py" collect <START> <END> \
  --pricing '<JSON>' --project-dirs -home-user-repo -home-user-repo-2
```

# 失敗したとき（ai-report）

単価の調査がうまくいかなかったとき、`python3` が動かないとき、定性パートが「（未記入）」になったとき、`report` が失敗したときに読む。

## 単価の調査に失敗したとき

`--pricing` を付けずに `collect` を実行してよい。コスト試算のセクションだけが省かれ、ほかの集計は通常どおり出る。その旨をユーザーに伝える。

## 同じファミリーの中で、世代ごとに単価が分かれていたとき

`family` では表せない。勝手にどちらかを採用せず、ユーザーに報告して判断を仰ぐ。

## `python3` が動かないとき

見つからない、`Python` とだけ出て失敗する、Microsoft Store の案内が出るなどのときは、`python3` を `python`、次に `py -3` に替えて、同じ引数で実行する。Windows では、Python を入れていても、`python3` が Store を開くだけの空のコマンドになることがあるため。手順 5 の `report` も、動いたほうで実行する。

どれも動かなければ、Python 3.9 以上を入れるようユーザーに伝えて終わる。

## 定性が「（未記入）」になったとき

手順 4 の Write をやり直してから、`report` を実行する。`report` は、`collect` が書く中間データ `.ai-report-data.json` と定性パート `.ai-report-qualitative.md` を読む。両ファイルは消さずに残す（削除は人が行う）。前の実行の定性パートを使わないよう、中間データより古い定性パートは読まない。

## `report` が「`.ai-report-data.json` が無い」で失敗したとき

手順 3 の `collect` からやり直す。

# 結果の伝え方（issue-pr-sync）

手順 6 で、ユーザーに結果を伝えるときに読む。

## 伝えること

- 反映した対象と、その URL。承認を取らずに反映した変更は、そのことを添える。PR を省いたときは使った PR の番号を、Issue をブランチ名から取ったときはそのことも書く
- 変更前の値（タイトル・サイドバー）と、反映前の本文（`_before.md`）の出力パス。戻す必要が出たときのため。パスの前後は、半角スペースか改行で区切る（規約は `aidd` の `README.md` の「出力先のパスは、前後を区切って伝える」）
- 反映しなかった対象と、その理由
- 本文の文字数（数えられなかったときは、その理由）
- PR 本文の「AI を使った確認」の自分の行：番号をどう直したかと、チェックを入れたか（入れなかったときは理由）
- ほかのコマンドの行にチェックを入れたとき：行ごとの根拠（この会話で実行した時点のコミットと、その結果）
- 判断を保留した論点があれば、その内容
- PR 本文を新しく作った場合は、最後に次の旨を添える

  > PR 本文の提案とレビュワー向けの動作検証ファイルを作りたい場合は `/aidd:pr-create` を使う（GitHub には反映せず `tmp/` に下書きを出す）。今回のように本文・タイトル・サイドバーを直接整えたい場合は `/aidd:issue-pr-sync`。目的に応じて使い分ける

## `/aidd:pr-create` との使い分け

| スキル | 作るもの | GitHub への反映 |
| --- | --- | --- |
| `/aidd:pr-create` | PR 本文の提案と、レビュワー向けの動作検証ファイル（検証コメント） | しない（`tmp/` に下書きを出すだけ） |
| `/aidd:issue-pr-sync` | Issue / PR の本文・タイトル・サイドバーの更新 | 直接反映する（重要な変更だけ承認を取る） |

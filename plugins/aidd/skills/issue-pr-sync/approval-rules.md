# 承認を取る変更（issue-pr-sync）

手順 3・4 で、変更が反映前に承認を取るものかを決めるとき、承認を求めるときに読む。

## 承認を取る変更

次の変更は、反映前に手順 4 で承認を取る。書いた人の意図を消したり、ほかの人に通知が届いたりするため。それ以外は承認なしで反映し、反映前の本文を `tmp/` に残して戻せるようにする。

| 承認を取る | 承認を取らない |
| --- | --- |
| 既存の記述を消す・意味を変える（追記・チェック以外の書き換え。500 文字に縮めるのも含む） | PR 本文の新規作成、「変更点」への追記、「AI を使った確認」のコマンドに番号を入れる・今の番号に直す、自分の行にチェックを入れる |
| 既存の記述と差分が食い違い、どちらを正とするか決めきれない | Issue のタスクのチェック、着手後に増えた対応の追記 |
| Issue のタイトルを変える | PR のタイトルを Issue に揃える |
| ラベル・担当者を外す。ほかの人を担当者・レビュワーに足す | ラベル・自分（または Issue の担当者）・マイルストーンを、Issue に揃えて足す |
| `Closes #<番号>` / `Ref:` を足す・付け替える | 新規作成で `Closes #<Issue番号>` を付ける（Issue のタスクが差分で埋まっているとき） |

## 聞き方

- 変更ごとに次を示す。全文は出さない
  - 本文：どのセクションの何を消す・書き換えるか。縮めるときは、縮める前と後の文字数も示す
  - タイトル：変更前 → 変更後
  - サイドバー：外す項目・足す人
- 既存の記述と差分が食い違っていて、どちらを正とするか決めきれない論点があれば、承認を求める前にユーザーへ示して判断を仰ぐ
- 断られた変更は外す。本文なら、その箇所を反映前の記述に戻した全文で反映する

# 出力テンプレート

`docs-sync` Skill が `tmp/<ブランチ名>/docs-sync_<yyyymmdd_hhmmss>.md` に書き出すレポート構造を定義する。

````markdown
# ドキュメント追従チェック結果

## サマリ

- 総合判定: PASS | FAIL
- 基準ブランチ: <解決された基準ブランチ>
- 変更ファイル: <総数>（md: <件数> / 非md: <件数>）
- 機械チェック FAIL 件数: N
- 追従判定 指摘件数: N（high: N / medium: N / low: N）
- 対象外の観点: <SKIP になった項目。無ければ「なし」>

## 機械チェック

### 相対リンク切れ（変更 md）

- PASS | FAIL
  - `<file>:<line>` → `<target>`

### markdown 規約

- PASS | FAIL
  - `<file>:<line>` `<rule-id>` `<内容>`

### docs-type フロントマター

- PASS | FAIL | 対象外（このリポジトリは docs-type 規約を使っていない）
  - `<file>` `<不備内容>`

### 全 docs リンク切れ（全走査）

- PASS | FAIL
  - `<file>:<line>` → `<target>`

### SSOT 一覧ポインタ存在（全走査）

- PASS | FAIL | 対象外（「唯一の情報源」列を持つテーブルがない）
  - `<対応表のファイル> SSOT 一覧` → `<path>`（参照先が実在しない）

## 追従判定（コード・インフラ変更への docs 追従）

> 参照した規約: `<探索で見つかった規約ファイル。無ければ「なし（一般的なベストプラクティスで判定）」>`

### high

- 対象 md: `<更新すべき docs>`
  - トリガー変更: `<変更された非 md ファイル>`
  - 不整合: `<実装と docs の食い違い>`
  - 推奨更新: `<どこを・どう直すか>`

### medium

- （同上の構造）

### low

- （同上の構造）

> 指摘が無いカテゴリは「指摘なし」と明記する。

## 推奨アクション

1. <優先度の高い順に対応すべき項目>
````

## 書き方のルール

- `SKIP` を返した項目は「対象外」と明記し、括弧内に理由を添える。**FAIL として書かない**
- 「対象外の観点」をサマリに出すことで、何を見て何を見ていないかが読み手に分かるようにする
- 追従判定のセクション冒頭に、探索で見つかった規約ファイルを列挙する。規約が無いまま「規約違反」と書かない

# ファイルの中の変更を分ける場合（commit）

`commit` の手順 6 で、1 つのファイルの中に目的の違う変更が混ざっていて、別々のコミットに入れるときに読む。

パッチを使う。パッチには、そのコミットに入れるハンク（差分の `@@` で始まるまとまり）だけを入れる。人は `tmp.md` の手順で、`git apply -v --cached <パッチ>` を実行してステージに置く。

## パッチの置き場所

パッチは、コミットごとに `tmp/<ブランチ名>/commit/<ts>_<N>.patch` に書く（`<ブランチ名>`・`<ts>` の取り方は `commit` の `SKILL.md` の「出力先」）。

- 1 回の提案で書くパッチには、同じ `<ts>` を使う
- `<N>` は、`tmp.md` の「コミット N」の番号

## 作り方

1. `git diff --cached -- <ファイル>` で、分けるファイルのハンクを見る
1. ハンクごとに、どのコミットに入れるかを決める
1. コミットごとにパッチを書く。中身は、分けるファイルごとの頭の行（`diff --git` の行から `+++` の行まで）と、そのコミットに入れるハンクにする
1. パッチがコミットの順に当たるかを、HEAD の中身の写しで確かめる（下の「順の確かめ」）。人が当てる前に、写し間違いと順の食い違いを見つけるため

## 順の確かめ

1. 分けるファイルごとに、`git show HEAD:<ファイル>` で HEAD の中身を取り、`tmp/<ブランチ名>/commit/<ts>_base/<ファイルのパス>` に写す。`<ts>` はパッチと同じにする
1. リポジトリのルートで、`git apply --check --directory=tmp/<ブランチ名>/commit/<ts>_base tmp/<ブランチ名>/commit/<ts>_1.patch tmp/<ブランチ名>/commit/<ts>_2.patch …` を 1 回だけ実行する。パッチは、コミットの順に並べる。最後のコミットの分は `git add` で入れるため、パッチは無い
1. 通らなければ、パッチを書き直して、もう一度実行する

`git show`・`git apply` は許可プロンプトが出るため、利用者に承認してもらう。`--apply` は付けない。写しにはステージを使わないため、`--cached` も付けない。

## 守ること

- 頭の行とハンクは、`git diff --cached` の出力から 1 文字も変えずに写す。行番号も直さない。前のコミットで行がずれても、`git apply` が前後の行から場所を探して当てるため
- 分けたファイルを最後に入れるコミットでは、そのファイルのパッチを作らない。残りを `git add <ファイル>` で入れる。前のコミットまでを当てた後は、残りの差分がちょうどそのコミットの分になるため
- 分けたファイルを、それより前のコミットで `git add` しない。後のコミットの変更まで入るため
- 分けたい変更が 1 つのハンクに入っているときは、`git diff --cached -U1 -- <ファイル>` で取り直す。前後の行を 1 行に減らすと、ハンクが細かくなるため。それでも分かれないときは、そのファイルを分けない
- 新しく足したファイル・消したファイル・名前を変えたファイル・バイナリのファイルは、中を分けない。ファイルごと 1 つのコミットに入れる
- 写しは、確かめた後も消さない。片付けは、`tmp/` を片付けるときに人が行うため

## `tmp.md` の書き方

`git add` のブロックに、`git apply -v --cached <パッチ>` の行を足す。`-v` を付けるのは、成功しても何も出ず、当たったかが分からないため。ブロックの最後には `git diff --cached --stat` を置き、ステージに入ったものを人が見られるようにする。次は、`<fileA>` の変更を 2 つのコミットに分け、コミット 1 に `<fileB>` も入れる例。

````markdown
コミット 1 — `<fileA>` の一部（パッチ）・`<fileB>`

```bash
git reset
git apply -v --cached tmp/<ブランチ名>/commit/<ts>_1.patch
git add <fileB>
git diff --cached --stat
```

`git apply` で失敗と出たら、もう一度当てずに、`--stat` の出力で当たっているかを見てください。やり直すときは `git reset` から始めてください。

```bash
<type>: <subject>

Why:
- ...

What:
- ...
```

コミット 2 — `<fileA>` の残り

```bash
git add <fileA>
```

```bash
<type>: <subject>

Why:
- ...

What:
- ...
```
````

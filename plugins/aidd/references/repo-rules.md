# リポジトリの決まりの探し方

スキルが同梱の決まり（書式・本文の長さ・文書の規約・雛形）を当てる前に、作業中のリポジトリに同じ話題の決まりがあるかを探す手順。同梱の決まりは、リポジトリに決まりが無いときの既定のため。決まりがあるのに同梱の決まりを当てると、`[Bug] fix: 〜` のように 2 つの形が混ざる。

## 探す

- 呼ぶ側が挙げた「話題の語」で、`CLAUDE.md`・`AGENTS.md`・`.claude/rules/`・`CONTRIBUTING.md`（`.github/` も）・`docs/` を Grep し、当たったファイルを Read する
- 呼ぶ側が設定ファイル（`.markdownlint*` など）や雛形の名前を挙げていれば、Glob で探して Read する
- 話題に触れているだけの記述（例として名前が出るだけなど）は、決まりとして扱わない。その話題の書き方・形・上限を決めている記述だけを使う

## 見つかったとき

- その話題には、リポジトリの決まりに従い、同梱の決まりを当てない。2 つを混ぜないため
- リポジトリの決まりが決めていない項目だけを、同梱の決まりで補う（例：書式の決まりはあるが、見出しの決まりが無い）
- リポジトリの決まり同士が食い違うときは、推測で選ばず、どちらに従うかを `AskUserQuestion` で聞く

## 見つからないとき

- 同梱の決まりを、そのまま当てる

## 伝える

- どれに従ったか（決まりのファイルのパス、または「既定」）を、承認の画面か結果に書く。利用者が、取り違えていないかを確かめられるようにするため

# マージ先（比べるブランチ）の決め方

差分を比べるブランチと、作業ブランチの起点を決める手順。`docs-sync`・`pr-create`・`issue-start` が使う。既定ブランチに決め打ちすると、`develop` に溜めてから `main` へリリースするリポジトリでは、未リリースの変更まで差分に混ざるため。

## 規約を探す

- `CLAUDE.md`・`.claude/rules/`・`CONTRIBUTING.md`（`.github/` 配下も）・`docs/` を「ブランチ」「branch」で Grep し、当たったファイルを Read する。今のブランチのマージ先を探すときは、「マージ先」も加える
- ブランチの種類（`issues/`・`develop`・`release/`・`stg` など）ごとのマージ先を読む。ブランチ戦略はリポジトリごとに違う（`develop → stg → main` など）ため

## 今のブランチのマージ先を決める

`docs-sync`・`pr-create` が使う。今のブランチは `git branch --show-current` で取る。次の順に当て、最初に決まったものを使う。

1. `gh pr view --json baseRefName` で、今のブランチの PR のマージ先を取る。PR が無ければ（コマンドが失敗したら）次へ進む
1. 規約にある、今のブランチの種類のマージ先を使う。今のブランチが「ほかのブランチのマージ先」として書かれているだけの記述は使わない。`develop` で「普段の PR は `develop` へ」を読むと、自分自身と比べてしまうため
1. どちらも無ければ、`pr-create` は既定ブランチ（多くは `main`）にする。`docs-sync` は決めずに、`--base` を付けない（スクリプトが既定ブランチ（`origin/HEAD`）と比べる）

## 作業ブランチの起点を決める

`issue-start` が使う。起点のブランチ（作業ブランチの作成元で、PR のマージ先）は、規約にあればそれ、無ければ `gh repo view` の `defaultBranchRef`（既定のブランチ）にする。`develop` に溜めてから `main` へリリースするリポジトリでは、既定のブランチと起点が違うため。`main` などに決め打ちしない。

## 比べる先を最新にする

`docs-sync`・`pr-create` が、マージ先と差分を比べるときに使う。

- 比べる先は `origin/<マージ先>` にする。手元のブランチは、GitHub でのマージに追いつかず古くなりやすいため
- 先に `git fetch origin <マージ先>` で最新にする。断られたら、手元の `origin/<マージ先>` のまま続け、古い可能性を報告に書く
- `origin/<マージ先>` が無いときだけ、手元の `<マージ先>` を使う

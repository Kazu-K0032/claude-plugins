# PR 本文の「AI を使った確認」の欄

`pr-create`・`issue-pr-sync` が、PR 本文の「AI を使った確認」の欄を書く・直すときの決まり。番号の形とチェックの入れ方を、2 つのスキルでそろえるため。

## 欄があるときだけ書く

- PR テンプレート（新しく作るとき）か、今の PR 本文（追従するとき）に欄があるときだけ書く。欄が無ければ足さない
- 見出しが「AIを使った確認」など違う表記でも、同じ欄として扱う

## 番号を入れる

各行のコマンドに番号を入れ、コピーしてそのまま実行できるようにする。

| コマンド | PR があるとき | PR がまだ無いとき |
| --- | --- | --- |
| `/aidd:issue-pr-sync` | `<Issue番号> <PR番号>` | `<Issue番号>` だけ（今のブランチの PR が使われる） |
| `/aidd:pr-review` | `<PR番号>` | 付けない（今のブランチの PR が使われる） |
| 番号を取らないもの（`/aidd:docs-sync`・`/marketplace-update` など） | 付けない | 付けない |

```markdown
- [ ] `/aidd:issue-pr-sync 41 42` で、Issue と PR の内容が合っているか確かめた
- [ ] `/aidd:pr-review 42` を実行し、指摘を確かめて直した
```

- Issue の番号は、本文の「関連 Issue」に書く番号を使う。複数あれば、Issue を取るコマンドは Issue ごとに 1 行にする
- PR の番号は、扱う PR の番号を使う（引数で渡された PR か、今のブランチの PR）。`issue-pr-sync` の実行では PR があるため、「PR があるとき」の形にする
- 行の説明文はテンプレートのまま変えない。番号が無い・片方しか無い・違う番号が入っている行は、表の形に直す

## チェックを入れる

- `issue-pr-sync` は、`/aidd:issue-pr-sync` で始まる行に入れる。実行した本人のため、確かめたと言える
  - Issue ごとに行が分かれているときは、この実行の Issue の行だけに入れる
  - 入れるのは、反映まで終えたとき（「更新不要」と判断したときも含む）。中断したときと、承認を断られた変更があるときは入れない
- ほかのコマンドの行（`/marketplace-update`・`/aidd:docs-sync`・`/aidd:pr-review` など）は、次をすべて満たすときだけ入れる。`pr-create` も同じ。Claude が自分で実行して結果を見たものは、確かめたと言えるため
  - この会話の中で、そのコマンドを実行し、結果を見た。会話が要約され、実行した時点のコミットと結果が分からないときは入れない
  - 実行した後に入ったコミットは、この欄のコマンドの指摘を直すものだけ。ほかの変更が入ったら、実行し直すまで入れない
  - 指摘が残っていない（直したか、直さずに残すと利用者が決めた）
- 条件を満たさない行には入れない。実行したかも、指摘を直したかも本文からは分からず、確かめたと判断するのは人のため
- ほかのコマンドの行に入れたときは、報告に行ごとの根拠（実行した時点のコミットと結果）を書く。人が確かめ、違えば外せるようにするため
- 既に入っているチェックは外さない

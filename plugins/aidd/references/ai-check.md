# PR 本文の「AI を使った確認」の書き方

`pr-create` と `issue-pr-sync` が、PR 本文の「AI を使った確認」の欄を書く・直すときの決まり。2 つのスキルが同じ形で書けるよう、ここを正典にする。

PR テンプレートにこの欄があるときだけ書く（「AIを使った確認」など表記が違ってもよい）。欄が無ければ足さない。`issue-pr-sync` は、追従・新規作成のどちらでも、この決まりのとおりに直す。

## 番号の入れ方

各行のコマンドに番号を入れ、コピーしてそのまま実行できるようにする。

| コマンド | PR があるとき | PR がまだ無いとき |
| --- | --- | --- |
| `/aidd:issue-pr-sync` | `<Issue番号> <PR番号>` | `<Issue番号>` だけ（今のブランチの PR が使われる） |
| `/aidd:pr-review` | `<PR番号>` | 付けない（今のブランチの PR が使われる） |
| 番号を取らないもの（`/aidd:docs-sync`・`/marketplace-update` など） | 付けない | 付けない |

```markdown
- [ ] `/aidd:issue-pr-sync 41 42` で、Issue と PR の内容が合っているか確かめた
- [ ] `/aidd:pr-review 42` を実行し、指摘を確かめて直した
```

- Issue の番号は、本文の「関連 Issue」に書く番号を使う。複数あれば、Issue を取るコマンドは Issue ごとに 1 行にする
- PR の番号は、今のブランチの PR の番号を使う。`issue-pr-sync` の実行では PR があるため、いつも「PR があるとき」の形にする
- 行の説明文はテンプレートのまま変えない。番号が無い・片方しか無い・違う番号が入っている行は、表の形に直す

## チェックの入れ方

- `pr-create` は、どの行にもチェックを入れない。実行したかを、本文を作る側からは確かめられないため
- `issue-pr-sync` は、`/aidd:issue-pr-sync` で始まる行にだけ入れる。実行した本人のため、確かめたと言える
  - Issue ごとに行が分かれているときは、この実行の Issue の行だけに入れる
  - 入れるのは、反映まで終えたとき（「更新不要」と判断したときも含む）。中断したときと、承認を断られた変更があるときは入れない
- ほかの行（`/marketplace-update`・`/aidd:docs-sync`・`/aidd:pr-review` など）には入れない。実行したかも、指摘を直したかも本文から分からず、確かめたと判断するのは人のため
- 既に入っているチェックは外さない

# Markdown 編集ルール

ドキュメントを書く・直すときの共通規約。

## SSOT（唯一の情報源）

- 同じ情報を 2 か所以上に書かない
- 既存ドキュメントに同じ内容があれば、本文をコピーせず相対パスでリンクする
- プロジェクトに「情報と唯一の情報源の対応表」があればそれに従う（`CLAUDE.md` や `docs/README.md` に置かれていることが多い）

## 文体

- 命令形・断定形で書く
- 前置き、結論の繰り返し、自明な説明を書かない
- 1 セクション = 1 トピックに絞る

### DO / DON'T

| DO | DON'T |
| --- | --- |
| `terraform apply で全リソースを作成する。` | `ここで terraform apply コマンドを実行すると全リソースが作成されます。` |
| `[commands.md](commands.md) を参照。` | コマンド一覧を本文に再掲する |
| 表・箇条書き | 長文段落 |

## 読者層

読み手に非エンジニア（PM・デザイナー・技術知識の少ないメンバー）が含まれるドキュメントは、誰もが理解できる言葉遣いにする。手順書・運用ログ・戦略・共有ナレッジがこれに当たる。

平易化の具体的な技法（用語のかみ砕き・Why 1 行・コマンドの説明・比喩など）は [plain-language.md](plain-language.md) を唯一の情報源とする。

## 構造

- 表または箇条書きを優先する
- 段落は 3 行以内に分割する
- コードブロックは「実行する／コピペする」目的に限る
- 見出しレベルは飛ばさない（`#` → `##` → `###`）

## 制約

- 1 ファイル合計 200 行以下を目標とする
- リンクは相対パスで書く（例: `[commands.md](commands.md)`）
- 1 ファイルにつき H1（`#`）は 1 つ
- 一時ファイル（`tmp` で始まる名前・`tmp/` 配下、その他「一時的」と明示されたもの）を本文から参照しない

## 適用対象外

外部システムのエクスポートや設定の現状を**あるがまま**記録する場所は本規約の対象外とする。重複排除（SSOT）・文体・行数の制約は適用せず、原データを忠実に残すことを優先する。

プロジェクトによって置き場所は異なる（`docs/design/`・`fixtures/` 等）。対象外の範囲はプロジェクト側の規約で判断する。

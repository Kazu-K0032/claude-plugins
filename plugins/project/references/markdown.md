# Markdown コーディング規約

markdownlint（vscode-markdownlint）のルールに準拠する。各規則の理由は、[markdownlint の Rules.md](https://github.com/DavidAnson/markdownlint/blob/main/doc/Rules.md) の Rationale による（MD052・MD053 と区切り行の規則を除く）。

## 見出し（Heading）

- **MD001** heading-increment: 見出しレベルは1つずつ増やすこと（レベルを飛ばさない）。飛ばすと文書の構造が分かりにくくなり、読み上げ機能では特に迷うため
- **MD003** heading-style: 見出しスタイルはATX形式（`#`）で統一すること。書式をそろえると、文書が読みやすくなるため
- **MD018** no-missing-space-atx: `#`の後にスペースを入れること。守らないと、正しく表示されないことがあるため
- **MD019** no-multiple-space-atx: `#`の後のスペースは1つだけにすること。余分なスペースは表示に影響せず、意味が無いため
- **MD022** blanks-around-headings: 見出しの前後に空行を1行ずつ配置すること。空行が無いと、見出しとして読み取らないパーサーがあるため
- **MD023** heading-start-left: 見出しは行頭から始めること。行頭から始まらない見出しは、見出しとして読み取られないため
- **MD024** no-duplicate-heading: 同じ内容の見出しを複数使用しないこと。見出しの文字からリンク先を作るパーサーでは、同じ見出しが衝突するため
- **MD025** single-h1: トップレベル見出し（`#`）はドキュメント内に1つだけにすること。H1 は文書の題名の役割を持ち、題名は 1 つだけのため
- **MD026** no-trailing-punctuation: 見出し末尾に句読点を付けないこと。見出しは文として書くものではないため

## リスト（List）

- **MD004** ul-style: 順序なしリストのマーカーは`-`で統一すること。書式をそろえると、文書が読みやすくなるため
- **MD005** list-indent: 同じレベルのリスト項目のインデントを揃えること。守らないと、正しく表示されないことがあるため
- **MD007** ul-indent: ネストされたリストのインデントはスペース2つにすること。2 つにすると、入れ子の項目が親の項目の本文とそろうため
- **MD029** ol-prefix: 順序付きリストのプレフィックスは`1.`で統一すること。書式をそろえると、文書が読みやすくなるため
- **MD030** list-marker-space: リストマーカーの後のスペースは1つにすること。守らないと、正しく表示されないことがあるため
- **MD032** blanks-around-lists: リストの前後に空行を1行ずつ配置すること。空行が無いと、リストとして読み取らないパーサーがあるため

## コードブロック（Code Block）

- **MD031** blanks-around-fences: コードブロックの前後に空行を1行ずつ配置すること。空行が無いと、コードブロックとして読み取らないパーサーがあるため
- **MD040** fenced-code-language: コードブロックには必ず言語を指定すること。中身の内容に最も合致する言語を選ぶこと（下記の選定基準を参照）。言語に合った色分けで表示されるため
- **MD046** code-block-style: コードブロックのスタイルはfenced（` ``` `）で統一すること。書式をそろえると、文書が読みやすくなるため
- **MD048** code-fence-style: コードフェンスのスタイルはバッククォート（` ``` `）で統一すること。書式をそろえると、文書が読みやすくなるため

### コードブロック言語の選定基準

中身の内容から最も合致する言語を選ぶ。迷った場合は「その内容をエディタで開くとしたら何のシンタックスハイライトを当てるか」で判断する。

| 言語 | 内容の例 |
| --- | --- |
| `bash` | シェルコマンド、環境変数定義（`KEY=value`）、`.env` ファイルの内容 |
| `powershell` | PowerShell固有のコマンド（`& ".\venv\..."`） |
| `python` | Pythonコード |
| `json` | JSONデータ |
| `yaml` | YAMLデータ |
| `toml` | TOMLデータ（`pyproject.toml` 等） |
| `markdown` | Markdownテンプレート・出力フォーマット例 |
| `text` | ディレクトリツリー（`├──`）、フロー図（`→`）、ファイルパス例、その他どの言語にも該当しない内容 |

## 空白・フォーマット

- **MD009** no-trailing-spaces: 行末の空白を残さないこと。改行のため以外の行末の空白は、意味を持たないため
- **MD010** no-hard-tabs: タブ文字を使用しないこと（スペースに置換）。タブはエディタごとに表示が変わり、スペースより扱いにくいため
- **MD012** no-multiple-blanks: 連続する空行は1行までにすること。コードブロックの外の連続した空行は、表示に影響しないため
- **MD047** single-trailing-newline: ファイル末尾に改行を1つ入れること。末尾に改行が無いファイルを、うまく扱えないプログラムがあるため

## リンク・画像

- **MD011** no-reversed-links: リンク構文の括弧の順序を間違えないこと（`[text](url)`）。括弧が逆のリンクは、リンクとして働かないため
- **MD034** no-bare-urls: URLはリンク形式で記述すること（`[text](url)`）。そのままの URL を、リンクにしないパーサーがあるため
- **MD039** no-space-in-links: リンクテキスト内の前後にスペースを入れないこと。書式をそろえると、文書が読みやすくなるため
- **MD042** no-empty-links: 空のリンクを作成しないこと。空のリンクはどこにも移動できないため
- **MD045** no-alt-text: 画像には代替テキスト（alt）を必ず指定すること。画像を見られない人に、内容を伝えるため
- **MD051** link-fragments: リンクフラグメントが有効な見出しを参照していること。見出しを変える・消すと、その見出しへのリンクが切れるため
- **MD052** reference-links-images: 参照リンクが定義済みのラベルを参照していること。定義の無いラベルを指すと、リンクにならず文字のまま表示されるため
- **MD053** link-image-reference-definitions: 未使用の参照リンク定義を残さないこと。使わない定義は表示に出ず、読む人を迷わせるだけのため

## テーブル

- **MD055** table-pipe-style: テーブルのパイプ書式を統一すること。先頭や末尾のパイプが無い表を、うまく読み取れないパーサーがあるため
- **MD056** table-column-count: テーブルの列数を各行で統一すること。列が多い行のセルはたいてい表示されず、中身が失われるため
- **MD058** blanks-around-tables: テーブルの前後に空行を1行ずつ配置すること。空行が無いと、表を正しく読み取れないパーサーがあるため
- 区切り行の`|`と`-`の間に半角スペースを入れること（`| --- |`）。書式をそろえると、文書が読みやすくなるため

## 強調・インライン

- **MD036** no-emphasis-as-heading: 強調を見出しの代わりに使わないこと。強調を見出しの代わりにすると、ツールが文書の構造を読み取れないため
- **MD037** no-space-in-emphasis: 強調マーカー内の前後にスペースを入れないこと。内側にスペースがあると、強調として表示されないため
- **MD038** no-space-in-code: コードスパン内の前後にスペースを入れないこと。たいていは書き間違いで、正しく表示されないことがあるため
- **MD049** emphasis-style: 強調スタイルは`*`で統一すること。書式をそろえると、文書が読みやすくなるため
- **MD050** strong-style: 太字スタイルは`**`で統一すること。書式をそろえると、文書が読みやすくなるため

## ブロッククォート

- **MD027** no-multiple-space-blockquote: ブロッククォート記号の後のスペースは1つにすること。書式をそろえると、文書が読みやすくなるため
- **MD028** no-blanks-blockquote: ブロッククォート内に空行を入れないこと。空行で分けた 2 つの引用を、1 つにまとめるパーサーがあるため

## その他

- **MD033** no-inline-html: インラインHTMLの使用を避けること（必要な場合を除く）。Markdown だけで書くと、HTML 以外の形式にも変換しやすいため
- **MD035** hr-style: 水平線のスタイルを統一すること（`---`を推奨）。書式をそろえると、文書が読みやすくなるため
- **MD041** first-line-h1: ファイルの先頭行はトップレベル見出しにすること（YAMLフロントマターがある場合は除く）。先頭の見出しが、文書の題名の役割を持つため
- **MD044** proper-names: 固有名詞の大文字小文字を正しく表記すること。固有名詞の大文字小文字の違いは、たいてい書き間違いのため

# docs

## このディレクトリは何か

このプロジェクトのドキュメントを置く場所。文書の性格ごとにサブディレクトリを分け、各サブディレクトリの `README.md` を案内板として運用する。

## いつ読むか

- どこに何が書いてあるか分からないとき
- 新しい文書を追加するとき（どのディレクトリに置くかを決めるため）
- 雛形（`*.template.*`）から実物を作るとき

## 書き方

- サブディレクトリは**最初の文書を作るときに作る**。空のディレクトリを先に用意しない。次のものだけは、最初から置く
  - `specs/`・`architecture/`：実物の雛形（`<実物の名前>.template.<拡張子>`）を置き、仕様と構成を同じ形で書き始められるようにするため
  - `adr/`：`CLAUDE.md` が一覧（`adr/README.md`）を読み込むため。ADR の雛形も置く
  - `strategies/`：AI 駆動開発の戦略と、開発・テストの進め方を、最初の作業から共有するため
- サブディレクトリを作ったら、同時にそのディレクトリの `README.md`（案内板）を置き、本ファイルの表からリンクする
- 案内板の構成は `.claude/rules/readme.md` に従う（`## このディレクトリは何か` → `## いつ読むか` → 一覧テーブルの順）
- 本ファイルに文書の本文を書かない。リンクで案内するだけにする

## 雛形から実物を作るとき

雛形は、実物を作るための見本で、実物ではない。実物を作ったら、雛形は要らなくなる。

1. 雛形を複製して、同じフォルダに実物を作る。名前は、雛形の名前から `.template` を除いたもの（例：`specifications.template.md` → `specifications.md`）。ADR のように名前に日付などを含むものは、実際の値にする。図の画像（`.png`）は複製せず、描き直した図から書き出す
1. `[例: ...]` と、雛形の先頭のコメントを、このプロジェクトの内容に書き換える。実物に残さない。構成図は、図の注記（「【雛形】」で始まる文字）を消し、ページ名から「（雛形）」を外す。本文の画像のリンクは、実物（`architecture.png`）に直す
1. そのフォルダの `README.md` の一覧に実物の行を足す。実物のパスは、`CLAUDE.md` の「参照ドキュメント」に `@import` で先に書いてあるため、足さない。ほかに常に読ませたい文書があれば、`@import` を足すことを提案する
1. 実物を作り終えたら、雛形の削除を利用者に提案する。削除は人が行う（Claude の削除は deny のため）。消したら、一覧の雛形の行も消す

# adr

## このディレクトリは何か

なぜその選択をしたかを、1 判断 1 ファイルで残す場所。戻しにくく、見送った案があり、理由をコードのコメントに書けない判断だけを残す（基準は `.claude/rules/adr.md`）。

## いつ読むか

- 技術的な判断をするとき、Issue に取りかかるとき（これまでの判断とずれていないかを確かめる）
- 同じことで迷ったとき

## ADR 一覧

`CLAUDE.md` がこの一覧を読み込み、Claude は題から関係する ADR を探す。題は「判断の対象: 決めたこと」の形で書き、題だけで何を決めたかが分かるようにする。

| --- | --- | --- |

## 書き方

- ファイル名は `YYYY-MM-DD-<判断の対象>.md`。結論やツール名は入れない
- ADR を足したら、上の表に 1 行足す。状態を変えたら、表の状態も合わせる
- `/aidd:adr` で作ると、重さ（極小・簡易・詳細）を選んで書き、この表に行を足す
- 手で書くときは、雛形の `YYYY-MM-DD-判断の対象.template.md` を見本にする。最初の ADR を作ったら、雛形の削除を利用者に提案する（手順は [docs/README.md](../README.md) の「雛形から実物を作るとき」）。以後は、直前の ADR を見本にして書く

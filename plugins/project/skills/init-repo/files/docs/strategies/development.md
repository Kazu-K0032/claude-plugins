# 開発の流れ

1 つの変更を、Issue から文書の追従まで、どの順で・誰が進めるかを決める。AI・機械・人の分担と、その理由は [ai-driven-development.md](ai-driven-development.md) にある。

## 進め方

| 順 | すること | 誰が | 残す先 |
| --- | --- | --- | --- |
| 1 | 何を作るか・なぜ作るかを決める | 人 | Issue |
| 2 | 仕様と判断を文書に書く | 人が決め、AI が下書きする | `docs/specs/`・`docs/adr/` |
| 3 | 実装する | AI | コード |
| 4 | 機械で検査する（編集後の Lint・整形、テスト、PR の CI） | 機械 | なし |
| 5 | 差分を読み、説明できたらコミットする | 人 | コミット |
| 6 | PR でレビューし、マージする | 人 | PR |
| 7 | コードと文書の食い違いを直す | AI が提案し、人が決める | `docs/` |

## なぜこの順にするか

- 文書（2）を実装（3）より先にする。AI の出力がずれたとき、人が文書と比べて判断できるようにするため
- 機械の検査（4）を、人が読む（5）より先にする。決まった規則の確かめを機械に済ませ、人は仕様や判断を読むことに時間を使うため
- 文書の追従（7）を、マージの後に回さない。食い違った文書は、次の作業で AI の誤った前提になるため

## aidd プラグインを使う場合

[aidd プラグイン](https://github.com/Kazu-K0032/claude-plugins) を入れていれば、各段を次のスキルで進められる。入れていなくても、上の流れは変わらない。

| 順 | スキル |
| --- | --- |
| 1〜5・7 | `/aidd:issue-start`（Issue の確認・要件の詰め・実装・文書の追従の点検・コミットメッセージの下書き） |
| 5 | `/aidd:commit` |
| 6 | `/aidd:pr-create`・`/aidd:pr-review` |
| 7 | `/aidd:docs-sync`（`/aidd:issue-start` を使わなかったとき） |

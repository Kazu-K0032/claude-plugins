# GAS のシートの見た目に関するルール

GAS でスプレッドシートのタブ（シート）を作る・書き換えるときの書式（フォント・色・枠線・列の配置と幅・見出しのメモ・プルダウン）を決める。タブを作るたびに書式を決め直さず、どのシートも同じ見た目で読めるようにするため。コードの置き場所と命名は `.claude/rules/gas.md`、実行時間の決まりは `.claude/rules/gas-runtime.md` にある。

テンプレートは、シートを操作するコードを配らない。下の決まりは、スプレッドシートのサービスのファイル（例：`spreadsheet.js`）を書くときに当てる。

## 見た目を決める場合

利用先に見た目の決まり（既存のシート・手本にするシート・規約）があれば、それに合わせる。無いときだけ、次の標準と、下の各節を使う。

| 項目 | 標準 |
| --- | --- |
| フォント | メイリオ。空のセルを含む、シートのすべてのセルに当てる。見出し行は 11pt、本文は 10pt |
| 見出し行 | 太字、塗りは薄い灰色（`#f3f3f3`）、中央・垂直中央。折り返しは、その列の本文と同じ |
| 枠線 | すべてのセルに、細い灰色（`#cccccc`）の実線を付ける |
| 固定 | 1 行目だけを固定する |

## 列の配置を決める場合

列ごとに、入る値の増え方で次の 3 つから選ぶ。同じ性質の列の配置がそろい、値を見比べやすくなるため。

| 配置（`layout`） | 入る値 | 水平・垂直・折り返し |
| --- | --- | --- |
| `short` | 数・日付・割合・カテゴリ・状態など、短いと決まっているもの | 中央・垂直中央・折り返す |
| `text` | 内容・メモ・講評など、文字数が増減するもの | 左・上・折り返す |
| `id` | ID のように、読む必要が無いのに文字数が多いもの | 左・垂直中央・切り詰める |

- 数・日付・割合・チェックボックスの列は、必ず `short` にする
- 切り詰めるのは `id` だけにする。ほかの列は、値を読めるように折り返す

## 列を定義する場合

シートと列の定義は、`constants.js` の `SHEETS` に集める。サービスのファイルが定義から書式を当て、列ごとの配置を機能のファイルに書かない。機能ごとに書くと、シートごとに見た目がずれるため。

| 項目 | 書くこと |
| --- | --- |
| シートの `name`・`description`・`remark` | シート名、何を持つシートか（概要）、誰が書くか・手で直してよいか（備考） |
| 列の `header`・`type` | 見出しの名前、表示形式（文字・日付・数・割合・チェックボックスなど） |
| 列の `layout`・`width` | 上の配置の種類、列の幅（px） |
| 列の `note` | 列の説明。何が入るか・単位・手で直してよいかを 1〜2 文で書く |
| 列の `list` | 入る値が決まっている列だけ。選べる値の一覧 |

- `note` は、見出しのセルのメモとして、実行のたびに書き直す。1 列目のメモには、シートの概要と備考も書く。定義を原本にし、メモを直すときは `constants.js` を直す
- `width` は、シートを新しく作るときだけ当てる。人が整えた幅を変えないため
- 定義が決まりに合うか（項目の書き忘れ・`short` にする列・`list` の重複）は、`tests/` のテストで確かめる。`tests/load-gas.js` で `constants.js` を読み込む

## プルダウンにする場合

- 入る値が決まっていて増えない列だけを、`list` を書いてプルダウンにし、一覧以外の入力を断る。値が増えうる列には、`list` を書かない
- `list` は、コードが使う値の定数と同じ一覧にする。同じ値を 2 か所に書かないため
- GAS は、入力規則が無いセルにだけ設定し、設定済みのセルは読み直して書き戻さない。人が画面で作った見た目が、書き戻しで保たれるかは、公式の文書で確かめられていないため
- 選んだ値を札で表示する見た目（チップ）と選択肢の色は、人が画面で決める。「データ」→「データの入力規則」で規則を開き、「詳細オプション」の表示スタイルでチップを選び、選択肢ごとに色を選ぶ。GAS からも Sheets API からも、指定する項目が公式のリファレンスに見当たらないため。Ref: [DataValidationBuilder](https://developers.google.com/apps-script/reference/spreadsheet/data-validation-builder)・[DataValidationRule](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/cells)
- `list` の値を変えたときは、画面で規則の値も直す。GAS は、設定済みの規則の値を直さないため
- 条件付き書式で、セルの背景に色を付けない。選択肢そのものの色とは別物のため
- 入力規則の読み書きは、列ごとに範囲でまとめて行う

## プルダウンの配色を決める場合

値ごとの色は、`constants.js` に一覧で書き、人が画面で色を決めるときに使う。値を見ただけで意味が分かり、シートをまたいでも色の意味がそろうようにするため。

- 意味（成功・失敗・進行中・完了・保留など）と色の系統の対応は、利用先で決め、この節に表で書く。色から受ける印象は、利用者によって違うため
- 未分類・その他など、決まっていない値は、灰色（`#d9d9d9`）にする
- 意味に当たらない値（カテゴリなど）は、意味に使った系統と重ならない系統から選ぶ
- 色は、すべてのプルダウンのすべての値で、重複させない。同じ系統の色が要るときは、次の表の淡い色から順に使う

| 系統 | 淡い順（1 つ目 → 3 つ目） |
| --- | --- |
| 赤 | `#f4cccc` → `#ea9999` → `#e06666` |
| 橙 | `#fce5cd` → `#f9cb9c` → `#f6b26b` |
| 黄 | `#fff2cc` → `#ffe599` → `#ffd966` |
| 緑 | `#d9ead3` → `#b6d7a8` → `#93c47d` |
| 青 | `#cfe2f3` → `#9fc5e8` → `#6fa8dc` |
| 紫 | `#d9d2e9` → `#b4a7d6` → `#8e7cc3` |
| 桃 | `#ead1dc` → `#d5a6bd` → `#c27ba0` |
| シアン | `#d0e0e3` → `#a2c4c9` → `#76a5af` |

## 余白の列を整える場合

使う列の右に、余白の列を 1 列だけ残し、それより右の空の列は削除する。画面の右側に、使わない列が並んで見づらくなるのを防ぐため。

- 残す余白の列は、定義の列数 + 1 列目で、幅は 20 にする。例：3 列を使うシートなら、4 列目を幅 20 で残し、5 列目以降を削除する
- 値が入っている列は削除しない。その列の右に 1 列だけ残す。人が書いた値を、知らないうちに消さないため
- 残す列・消す列を決める判定は、GAS のサービスを使わない関数に分け、テストで確かめる。列の削除は戻せないため
- 何度実行しても、同じ結果になるようにする

## 案内のシートを作る場合

シートの一覧を載せた「案内」のシートは、作るかを利用先で決める。作る場合は、次に従う。

- `SHEETS` の定義から、シート名・概要・備考の一覧を、実行のたびに作り直す。一覧を別に書かない。シートを足したときに、載せ忘れないため
- 「案内」は `SHEETS` の先頭に置き、備考に、手で直しても次の実行で消えることを書く
- シート名は、シートの番号（gid）で指すリンクにする。名前を変えても、リンクが切れないため

## 書式を設定する場合

- 書式の値（フォント名・色・サイズ・配置の種類）は `constants.js` に、書式を当てる関数はスプレッドシートのサービスのファイルに置く。複数のタブで使うため、機能ごとに書くとタブごとに見た目がずれる
- 書式は、範囲全体にまとめて設定する。セルごとに呼ぶと、実行時間の上限に近づくため（`gas-runtime.md` の「時間のかかる処理を書く場合」）
- 既存のタブの書式は、承認なしに変えない。利用者が手で整えた見た目を、知らないうちに変えないため
- ただし、1 行目の見出しが空の既存のタブは、作りたてと同じに整える（見出し・書式・固定・列の幅）。人が空のタブだけを作ったときに、見出しの無いまま残らないようにするため

# 導入後にやること

`gas` の手順 8 で、コピーが終わった後に、残作業と、土台に残る GAS と合わない箇所を利用者に示す。既存のプロジェクトで済んでいる項目は省く。

## 残作業

1. clasp を入れてログインする（`npm install -g @google/clasp` → `clasp login`）。初回は [Apps Script のユーザー設定](https://script.google.com/home/usersettings) で Google Apps Script API を有効にする
1. Apps Script のプロジェクトを用意し、エディタの「プロジェクトの設定」にあるスクリプト ID を `.clasp.json` の `scriptId` に書き込む
1. 既にコードがあるプロジェクトにつなぐ場合は、push の前に `clasp pull` で取り込み、手順 6 の振り分けを行う。pull するとリモートと同じ名前のローカルファイルはリモートの内容で上書きされる
1. `src/constants.js` の `TODO:` を埋める。秘匿値はエディタの「プロジェクトの設定」→「スクリプト プロパティ」に登録し、キー名を `PROPERTY_KEYS` に書く
1. `clasp push` で反映し、定期実行を使う場合はエディタから `setupTriggers` を 1 回実行する（初回は権限の承認を求められる）。以後も毎回同じ Google アカウントで実行する。`setupTriggers` は実行したアカウントのトリガーをすべて消してから `TRIGGERS` の分だけ作り直すため、そのアカウントで手作業で作ったトリガーも消える（手順 6 で一覧に書き移したものは作り直される）。別のアカウントで作ったトリガーは残る。定期実行を使わない場合は `trigger.js` の雛形を消す
1. `setupTriggers` を実行したら、「トリガー」画面の件数が `TRIGGERS` の件数と合うかを確かめる。多ければ、オーナーが「他のユーザー」のトリガーを、持ち主のアカウントで消してもらう

## 土台のうち GAS に合わない箇所

`init-repo` の土台は、Web アプリのように、ローカルで動かしてデプロイする構成を前提にした文を含む。GAS にはローカルの実行環境も、デプロイ用のワークフローも無いため、そのままでは手順が合わない。このスキルは土台のファイルを書き換えない（P6）。表を示し、直すかどうかは利用者に決めてもらう。リポジトリに無いファイルの行は省く。

| 箇所 | 土台の前提 | GAS での書き方の例 |
| --- | --- | --- |
| `README.md` の「各環境のリンク」 | ローカル・本番・検証の URL | 「ローカル」は、Apps Script エディタの URL（`https://script.google.com/home/projects/<scriptId>/edit`）に置き換える。開発用と本番用でプロジェクトを分けるなら、それぞれの URL と、紐づくスプレッドシートの URL を書く。使わない見出しは消す |
| `.github/ISSUE_TEMPLATE/release.yml` の「リリース手順」と「事前確認」 | リリース用ブランチへのマージと、デプロイワークフローの成功の確認 | 「`clasp push` で本番の Apps Script に反映する」「Web アプリなら、デプロイの版を更新する」「本番のスプレッドシートで動作を確かめる」に置き換える。ワークフローで自動デプロイしないなら、ワークフローの項は消す。「検証環境で動作確認」は、開発用のプロジェクトで確かめる、に直す |
| `.github/PULL_REQUEST_TEMPLATE.md` の確認項目 | 「ローカル環境で表示・動作確認した」 | 「開発用の Apps Script（テスト用のスプレッドシート）で動作確認した」に直す |
| `.claude/rules/env.md` の「変数の種類と追記先」の表 | `.env` を読む仕組みと `.env.example` への追記 | `.env` の行を消し、「スクリプトプロパティ」の行にする。読む仕組みは `getScriptProperty_`（`utils.js`）、追記先は `constants.js` の `PROPERTY_KEYS`（キー名だけ。値は書かない） |
| `CLAUDE.md` の「『反映されない』と判断する前」の `TODO` | Docker のマウント元・ビルド成果物の出力先 | 反映先は `.clasp.json` の `scriptId` の Apps Script プロジェクトで、push の対象は `rootDir`（`src/`）配下だと書く。反映されないときは、push したか、エディタ側が新しくないか（`clasp pull`）、Web アプリならデプロイの版を更新したかを先に確かめる |

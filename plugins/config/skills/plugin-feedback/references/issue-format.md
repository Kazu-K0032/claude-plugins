# Issue・コメントの本文の型

`Kazu-K0032/claude-plugins` の既存の Issue（#7・#8・#9 など）と同じ形で書く。

## 目次

- 共通の書き方：タイトル・文体・長さ・根拠の書き方
- 不具合（`bug`）：不具合の本文の型
- 改善案（`enhancement`）：改善案の本文の型
- 承知の上で求める理由：閉じた件・方針とずれる件を起票するときに足す節
- 既存の Issue へのコメント：コメントで追記するときの型
- 公開前の点検：下書きから消す・言い換える情報

## 共通の書き方

- タイトルは、何をするか・何が起きるかを 1 文で書き、動詞で終える（例：`〜を追加する`・`〜を見直す`・`〜を誤検出する`）。対象が複数あれば括弧で添える
- 文体は「だ・である」。1 文 1 事柄で書く。前置き・あいさつ・絵文字は書かない
- 長さは [short-body.md](short-body.md) に従う。1 文・1 項目は 50 文字以内、本文全体は 500 文字以内。コメントも同じ
- ファイル・スキル・コマンドの名前は、コードスパンで正確に書く（例：`plugins/project/skills/gas/SKILL.md`・`/project:gas`）。パスはこのリポジトリ内のパスで書き、利用先のパスは書かない
- 作業項目と未決の論点は `- [ ]` のチェックボックスで書く
- 番号付きリストは `1.` で統一する。コードブロックには言語を付ける（エラー文・出力は `text`）
- 関連する Issue は `#<番号>` で書く。末尾にまとめる場合は `関連: #<番号>（<一言>）` とする
- 公式ドキュメントなどの根拠は、引用 → 和訳 → 引用元の順で書く。引用は 1〜2 文にし、長ければ引用元のリンクだけにする。手で確かめた挙動には、確かめた日付を添える

```markdown
> The function won't show up in the editor's run drop down box.
> → その関数は、エディタの実行プルダウンに表示されない。

引用: [ページの題名](https://example.com/)（出典の名前、公開日）
```

## 不具合（`bug`）

`## 原因` は、裏が取れた範囲だけを書く（ファイルのパスと該当の行）。分からなければ節ごと書かない。`## 決めること` は、直し方に選択肢があるときだけ書く。エラー文・出力は、要る行だけを貼る。500 文字に数えるため。

````markdown
## 何が起きたか

`<プラグイン>:<スキル>` で〜したところ、〜になった。期待した動きは〜。

```text
<エラー文・出力>
```

## 原因

`<ファイルのパス>` の〜が〜しているため。

## 再現手順

1. 〜
1. 〜

## 決めること

- [ ] 〜

関連: #<番号>（<一言>）
````

## 改善案（`enhancement`）

`## 注意点` と `## 決めること` は、あるときだけ書く。

```markdown
## 背景

<どの作業で、何に困ったか・何があると便利か>

## やりたいこと

- [ ] 〜

## 注意点

- 〜

## 決めること

- [ ] 〜

関連: #<番号>（<一言>）
```

## 承知の上で求める理由

対応しないと決めて閉じた件や、方針とずれる件を起票するとき（`SKILL.md` の手順 4・5）だけ、不具合・改善案の本文に足す。`## 決めること` の前に置き、当てはまらない行は消す。価値・方針へのリンクは GitHub の URL で書く。Issue の本文では、相対パスのリンクが効かないため。

```markdown
## 承知の上で求める理由

- 閉じた Issue：#<番号>（<閉じた理由>）
- ずれる方針：[P<番号>](https://github.com/Kazu-K0032/claude-plugins/blob/main/docs/policies/<ファイル名>) の「<該当の文>」
- 求める理由：<ユーザーが書いた理由>
```

## 既存の Issue へのコメント

見出しで追記であることを示し、上の型の節を短く使う。同じ件なら、新しく分かったことだけを書く。

```markdown
## 追記: <一言の見出し>

### 何が起きたか

〜

### 再現手順

1. 〜
```

## 公開前の点検

`Kazu-K0032/claude-plugins` は公開リポジトリである。下書きから次の情報を消すか、言い換える。

| 情報 | 扱い |
| --- | --- |
| 利用先のリポジトリ名・組織名・プロジェクト名 | 「利用先のプロジェクト」「GAS を使う別のプロジェクト」などの一般的な言い方にする |
| ホームディレクトリ・ユーザー名を含む絶対パス | `~/...` にするか、このリポジトリ内のパスにする |
| メールアドレス・人名・アカウント名 | 書かない |
| トークン・鍵・パスワードらしい文字列（`ghp_`・`github_pat_`・`sk-`・`xox`・`AKIA`・`-----BEGIN` で始まるもの等） | 書かない。エラー文に含まれていたら `<redacted>` に置き換える |
| 社内の URL・ホスト名・IP アドレス | `<internal-url>` などに置き換える |
| 業務のファイルの中身・関数名・データ | 再現に要る最小限の汎用的な形に縮める（テンプレートにある名前に置き換える等） |

言い換えた箇所は、承認を取るときにユーザーへ伝える。承認を省いた場合は、作成した後の報告で伝える。

# Issue・PR の本文の長さ

Issue・PR の本文とコメントを、人が読み切れる長さに収める。長い本文は読まれず、人が中身を分からないまま通してしまうため。

## 上限

| 対象 | 1 文・1 項目 | 本文全体 |
| --- | --- | --- |
| Issue・PR の本文、Issue・PR へのコメント | 50 文字以内 | 500 文字以内 |
| 検証コメント（`pr-verify`） | 50 文字以内 | 上限なし |

検証コメントに全体の上限が無いのは、項目の数が差分で決まるため。

## 数え方

- 人が見える文を数える。見出し・記号（`#`・`-`・`[ ]` など）も数える
- 数えないもの：HTML コメント、改行、行頭・行末の空白、リンクの URL（`[文字](URL)` は文字だけ数える）
- 定型の節は数えない。見出しに「チェックリスト」か「関連 Issue」を含む節で、下位の見出しも含む。PR ごとに中身が変わらないため
- 1 項目は、箇条書きの 1 項目の全体。1 文は、地の文の `。` までを数える
- 見出し・表・引用・コードブロックは、50 文字の確かめの対象外。500 文字には数える

## 書き方

- 詳細は書かず、処理の流れを平易に書く（例：「〇〇したとき、〇〇される」）。細部は PR の「Files changed」で見られる
- 技術的な内容は、引用かリンクで示す。引用は 1〜2 文にし、長ければリンクだけにする
- 判断の理由は、短くても残す
- 調べた経緯・同じ内容の繰り返し・前置きは書かない

## 既存の本文を直すとき

- 500 文字を超えていれば、全体を縮める。見出しは残し、中身を言い換えて短くする
- 既存の記述を消す変更になるため、反映前に承認を取る。縮める前の本文は `tmp/` に残す

## 確かめ方

書き終えたら、同梱のスクリプトで数える。超えていたら縮め、もう一度数える。スクリプトは、このファイルから見て `../scripts/body_length.py` にある。実行するパスは、各スキルの参照ファイルの表に書いてある。

```bash
# 下書きのファイルを数える
python -B <スクリプト> <下書きのファイル>
# 検証コメントは、1 項目の長さだけを確かめる
python -B <スクリプト> --item-only <検証コメントのファイル>
# 下書きのファイルを作らないときは、標準入力から渡す
python -B <スクリプト> - <<'__BODY__'
<下書き>
__BODY__
```

- 出力の「全体」と「50 文字を超える項目・文」を読む。終了コードは、上限内なら 0、超えていれば 1
- `allowed-tools` には入れない。同梱のスクリプトの実行のため、許可プロンプトが出る
- `python` が無い環境では、`python3` で実行する

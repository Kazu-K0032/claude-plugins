# P6 土台には設計思想だけを入れ、技術に依るものは技術別のスキルで重ねること

| 区分 | 内容 |
| --- | --- |
| 対象 | `project`（`init-repo`・`gas`・`wordpress`・`terraform`） |
| 例外 | `init-repo` の `settings.json` の `env` に入れる `PYTHONDONTWRITEBYTECODE=1` は、Python 専用だが配る。Claude の作業スクリプトは、リポジトリの言語に関係なく Python で書かれやすく、入れても害が無いため。`commitlint.config.mjs` は Node のプロジェクトが前提だが配る。コミット規約の検証は土台の考え方で、Node はその道具にすぎないため。入れる条件で Node のプロジェクトに絞る。`lefthook.yml` の `commit-msg` は、commitlint を呼ぶ形でどのリポジトリにも配る。commitlint が入っていなければ飛ばすため、Node でないリポジトリでも害が無い |
| 価値 | [V5](../values/v05-mechanisms-over-habits.md) |

土台（`init-repo`）は、このリポジトリのハーネスの設計思想を配る。技術スタック別のスキル（`gas` など）は、その上に技術に依るものを重ねる。土台だけでも思想を受け継げ、技術別のスキルを重ねても思想が崩れないようにする。

## 土台に入れるもの

| 区分 | 入れるもの |
| --- | --- |
| 設計思想 | 権限の線引き（P1）、推論（Claude）と機械の検査の分担、`tmp/` の置き方、ADR、README の案内板、AI が読む文書の書き方（P9）、GitHub の定型（Issue・PR のテンプレート・ラベル・dependabot） |
| 土台自身が動くのに使う技術 | フックの bash・jq、ワークフローの YAML、CI で cspell を動かす Node、Lint・整形を動かす lefthook |

特定の言語・ツール向けの動く設定（ESLint の設定、言語の拡張子の一覧、特定のツールの破壊的な操作の検出など）は入れない。README の「除外したもの」に理由を書く。例示の文で技術名を出すのはよい。

## 技術別のスキルが足してよい場所（差し込み口）

| 場所 | 足すもの |
| --- | --- |
| `.claude/settings.json` | フック（`hooks`）と、その技術の秘匿ファイルの deny |
| `.gitignore` | その技術が作る秘匿ファイル・生成物の除外（例：`.clasprc.json`）。足す行は、承認を得てから足す |
| lefthook の設定（`lefthook.yml` など）の `claude-edit` | その技術の Lint・整形のツール |
| `.claude/hooks/post-edit-lint.sh` の言語別のブロック（前の版の形だけ） | その技術の Lint。`lefthook` を呼ばない前の版のフックが残る利用先との互換のため |
| `.claude/hooks/guard-destructive.sh` の `patterns` | その技術の破壊的な操作 |
| `cspell.json` の `words` | テンプレートが使う語 |
| `.claude/rules/<技術>.md` | その技術の規約（新しいファイル）。5,000 文字に収まらなければ、同じ `paths` を付けた `<技術>-<話題>.md` に分ける（[P9](p09-readable-ai-docs.md)） |
| `docs/adr/` | その技術の判断の ADR |

技術別のスキルは、次を守る。

- 土台の規約（P1 の線引き・ADR の置き場所・README の案内板・`tmp/`）に沿う。土台に無い考え方を持ち込まない
- 土台のファイルには、差し込み口にだけ、差分を示して承認を得てから足す
- 土台が無ければ、先に `/project:init-repo` を実行するかを聞く

## 理由

- 【役割分担】土台に技術の設定が混ざると、思想だけを入れたいリポジトリに関係の無い設定が入り、どのスキルが何を受け持つかが分からなくなるから
- 【使い回し】技術やプロジェクトで変わるものを土台に入れると、多くのリポジトリで書き換えや削除が要るから
- 【判断の一貫性】配らないと決めた理由が、別のスキルで知らないうちに崩れないようにしたいから

## Q&A

### Q. 受け持つ技術別のスキルが無い言語の設定（例：ESLint）を、土台に入れたい

入れない。Lint・整形のツールは、`init-repo` の手順 5 でプロジェクトごとに決めて `lefthook.yml` に書く。言語の規約や構成まで配りたいなら、その言語の技術別のスキルを足す。

### Q. 技術別のスキルが、土台のファイルの差し込み口以外を変えたい

変える前に利用者に伝え、差し込み口を増やす（上の表に足す）か、変えるのをやめるかを選んでもらう。

### Q. `init-repo` が配らないファイル（例：ビルドの CI）を、別のスキルで作りたい

`init-repo`・`gas`・`wordpress`・`terraform` の README の「除外したもの」で理由を読み、食い違わないかを確かめる。言語別のルールは「技術によって違う」ため除外しているので、技術別のスキルが配るのは理由に合っている。

### Q. 除外した理由と食い違う

作る前に利用者に伝え、除外をやめるか、作るのをやめるかを選んでもらう。除外をやめるなら、README の「除外したもの」の表から消す。

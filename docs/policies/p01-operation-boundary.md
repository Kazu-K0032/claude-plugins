# P1 Claude に任せる操作と、人が行う操作を分けること

| 区分 | 内容 |
| --- | --- |
| 対象 | すべてのプラグイン |
| 価値 | [V3](../values/v03-human-judgment.md)・[V5](../values/v05-mechanisms-over-habits.md) |

Claude が実行してよい操作と、人が行う操作の線引きを決める。新しい操作が出てきたら、下の「判断の順番」に当てて決める。

## 判断の順番

1. 削除・権限の変更・コミット・push は禁止する
1. 取り消せない操作のうち、間違えたときに深刻なものは禁止する
1. それ以外は許可する

「禁止」は、deny やスキルの禁止事項で止め、人が行うこと。「許可」は、deny に入れないこと。実行前に許可プロンプトを出すかは、下の「確認なしで任せる操作」で決める。

## 理由

- 【削除系】消したものは履歴を追えず、Claude に任せて席を外していると、消えたことに気づけないから
- 【権限変更系】間違えると、ほかの人やほかのサービスにまで影響が広がるから
- 【コミット】履歴に残す内容は、人が最後に確かめて決めたいから（`aidd:commit` がメッセージを `tmp.md` に書き出すのもこのため）。また、Claude Code がコミットすると、設定によっては共同作成者の行（`Co-Authored-By`）が付き、push した後は履歴を書き換えないと消せないから
- 【push】ほかの人へ共有するタイミングは、人が決めたいから
- 【それ以外】Issue・PR・コメント・ブランチは、意図しない内容ができても、消せば戻せるから。止めると、スキルが動かなくなるから

## 許可する操作と禁止する操作

| 対象 | 許可する | 禁止する |
| --- | --- | --- |
| 手元のファイル | 読み取り・作成・編集 | 削除 |
| Git | ブランチ・タグの作成、`git fetch` | コミット、push、`git remote` の変更、ブランチ・タグ・stash の削除、`.git/` の直接の書き換え（フック・設定の変更） |
| Issue・PR | 作成、コメント、本文・ラベル・担当者の更新、クローズ | 削除、マージ、レビュー（承認） |
| GitHub のそのほか | 読み取り | リリース、ワークフローの実行、リポジトリの作成・設定変更・削除、secrets・variables・鍵・ログインの変更 |
| 外部ツール | 読み取り | リモートとの反映・取り込み（`clasp push`・`clasp pull` など）、ログイン |

`init-repo` は、この表の禁止を deny で配る。スキルの操作との対応は [permissions.md](permissions.md)。deny は、ルールの形に当たるコマンドしか止められない。`bash -c 'rm …'` や、`gh api` での権限の変更は止まらない。抜けやすい形のうち、`gh api` でのマージと、`git -C`・`git -c` を付けたコミット・push は個別に止めている。deny で止まらない操作も、この線引きに従う。

あわせて、`settings.json` の `attribution` の `commit`・`pr` を空文字にし、コミットに共同作成者の行を、PR の本文に生成元の行を付けない。コミットの禁止が外れても、Claude の名前が履歴に残らないようにするため。

取り消せないが深刻でない操作は、許可する。たとえば、コメントや担当者の追加で届く通知、`tmp/` のレポートの上書き、テストの実行。

## 許可するときの条件

許可する操作のうち、やり方によっては害が出るものと、守る条件を書く。

### 既存のファイルを上書きするとき

承認なしに上書きしない。差分を見せて、「上書き・手でマージ・据え置き」から選んでもらう。利用者が書いた内容を、知らないうちに消さないため。

### 作業用の一時ファイルを作るとき

`tmp/<ブランチ名>/` に置く。削除は禁止なので、消さずに済む場所に置く。

### settings.local.json に書き込むとき

リポジトリの `.claude/settings.local.json`（個人用の設定）には、次の条件で書き込んでよい。切り替えをプロジェクトごとに見える場所に置けて、コミットもされないため。

- 足すのは、そのスキルが使うキーだけ。ほかのキーと書式は変えない
- 書き込むのは、そのキーの値がどこにも無いときだけ。このファイルの値はほかの場所より優先され、設定済みの値を上書きしてしまうため
- 書き込みを止められたら、書かずに既定の値で続ける

## 確認なしで任せる操作

スキルの `allowed-tools`（許可を聞かずに実行してよい操作の一覧）には、読み取りと、書き込み先が `tmp/` の下に決まっているものだけを入れる。書き込み先が決まらない操作、`gh` の書き込み、同梱スクリプトの実行は入れない。確認なしで任せる範囲を、取り返しのつく所に限るため。

## 変えたいとき

- deny から外すと、Claude もその操作をできる。外す・足す前に、止まるスキルを [permissions.md](permissions.md) で確かめる
- 許可プロンプトを減らしたいときは、自分の `settings.json` の `permissions.allow` に足す

## Q&A

### Q. 新しい操作が、許可か禁止か迷う

「判断の順番」に当てる。取り消せない操作は、間違えたときに何が起きるかで決める。マージ・リリース・本番への反映のように、ほかの人やサービスに効くものは禁止する。

### Q. スキルの最後に、コミットまで済ませたい

しない。メッセージは `tmp.md` に書き、コミットは人が行う。

### Q. 作業で作ったファイルを消したい

消さない。最初から `tmp/<ブランチ名>/` に置き、残したままにする。どうしても消すなら、コマンドを示して人に実行してもらう。

### Q. スキルの結果を、Issue や PR にコメントしたい

してよい。`gh` の書き込みは `allowed-tools` に入れず、許可プロンプトを通す。投稿前に承認を取るかは、スキルごとに決める。

### Q. 入れようとしたファイルが、利用先にもうある

上書きせず、差分を見せて選んでもらう。`project` のスキルは、`scripts/install.sh` がこの判定（NEW / SAME / DIFF）をする。

### Q. 同梱スクリプトを、許可なしで動かしたい

`allowed-tools` に入れない。`${CLAUDE_PLUGIN_ROOT}` が `allowed-tools` の中で展開されるかが、公式に書かれていないため。

### Q. スキルの切り替え（環境変数など）を、どこに置く？

プロジェクトごとに変えたいなら、上の条件で `.claude/settings.local.json` の `env` に置く。どのプロジェクトでも同じでよいなら、`~/.claude/settings.json` に置く。共有の `.claude/settings.json` には書かない。

### Q. ログインが切れていて、スキルが先に進めない

ログインのコマンドを示し、人に実行してもらう。

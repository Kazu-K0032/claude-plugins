# 設計の方針

3 つのプラグイン（`aidd`・`config`・`project`）を作る・直すときに守る決めごとと、その理由をまとめる。実装で迷ったら、一覧の「読む場面」から方針を探し、そのファイルの Q&A を読む。

## 一覧

| 番号 | 方針 | 読む場面 |
| --- | --- | --- |
| [P1](p01-operation-boundary.md) | Claude に任せる操作と、人が行う操作を分けること | コマンドや外部への操作を、Claude に任せてよいか迷うとき |
| [P2](p02-settings-scope.md) | 設定の置き場所をプラグインで分けること | 新しいスキルを、どのプラグインに入れるか決めるとき |
| [P3](p03-no-auto-mkdir.md) | 勝手にディレクトリを作らないこと | 出力先のディレクトリが無いとき |
| [P4](p04-tmp-output.md) | 下書きとレポートは tmp に出すこと | レポート・下書き・一時ファイルの置き場所を決めるとき |
| [P5](p05-rules-copy.md) | 常に効かせたい規約はリポジトリへコピーして配ること | 規約や判断基準の置き場所を決めるとき |
| [P6](p06-cross-plugin-copy.md) | プラグインをまたぐファイルはコピーで持つこと | ほかのプラグインのファイルを使いたいとき |
| [P7](p07-excluded-files.md) | 除外したものを作るときは除外の理由を確かめること | `init-repo`・`gas` が配らないファイルを作るとき |

スキルの操作と、`init-repo` が配る権限設定との対応は [permissions.md](permissions.md) にまとめる。

## 用語

| 用語 | 意味 |
| --- | --- |
| deny | `settings.json` の `permissions.deny`。ここに当たる操作は、Claude が実行できない |
| `allowed-tools` | スキルの冒頭（frontmatter）に書く、許可を聞かずに実行してよい操作の一覧 |
| 許可プロンプト | Claude が操作する前に、実行してよいかを利用者に聞く確認 |
| `guard-git-write.sh` | `init-repo` が配る、Git と GitHub への書き込みを止めるフック。既定では使われていない（`settings.json` に登録していない） |

## ファイルの書き方

方針を足すときは、次の形で 1 方針 1 ファイルを作り、上の一覧と `.claude/rules/repo-consistency.md` の一覧に行を足す。

```markdown
# P<番号> <方針>

<何をするか・しないかを 1〜2 文で>

## 理由

## 対象と例外

## 変えたいとき

## Q&A

### Q. <実装で迷う場面>

<どうするか。理由>

## 経緯
```

- 方針は「〇〇すること」の形で書く
- ファイル名は `p<2 桁の番号>-<英語の短い名前>.md` にする
- 番号は使い回さない。廃止した方針の番号は欠番にする。古いリンクや「P5 のため」といった記述が、別の方針を指さないようにするため
- 「変えたいとき」には、利用者ができること（deny に足す・環境変数で切り替えるなど）を書く
- 「Q&A」には、実装で迷う場面を Q に、どうするかとその理由を A に書く。迷う場面が新しく見つかったら足す
- 「経緯」には、方針を決めた・変えたときに何が起きて、どう決めたかを書く。リンクを開かなくても分かる文にし、最後に Issue へのリンクを添える
- 書くことが無い節は省く
- `docs/` はプラグインと一緒に配られない。スキルの本文から `docs/` を読ませない（[P6](p06-cross-plugin-copy.md) と同じ理由）

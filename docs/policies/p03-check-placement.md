# P3 ADR などの文書は、プロジェクトの規約どおりの場所に置くこと

| 区分 | 内容 |
| --- | --- |
| 対象 | `aidd:adr`（ADR の置き場所）、`project:init-repo`（README から移す本文の置き場所） |
| 対象外 | 置き場所をスキルが決めているもの（`tmp/<ブランチ名>/`、`~/.claude/` の設定、テンプレートのファイル） |

ADR のように、置き場所がプロジェクトごとに違うファイルを作るスキルは、リポジトリの規約（`CLAUDE.md` など）で場所を確かめる。規約に無ければ、候補を挙げて利用者に聞く。ディレクトリを作ること自体は止めない。

## 理由

- 【規約とのずれ】推測した場所に置くと、規約と違う場所に文書ができ、あとから探せなくなるから

## 変えたいとき

- 置き場所を決めておきたいときは、リポジトリの規約（`CLAUDE.md` など）にパスを書く

## Q&A

### Q. 規約で決めた場所に、ディレクトリが無い

作ってよい。場所は規約で決まっているため。

### Q. 規約に置き場所が書かれていない

似た名前のディレクトリ（例：`docs/adr/`・`docs/decisions/`）を探し、候補を挙げて利用者に聞く。推測した場所には置かない。

### Q. 置き場所がプロジェクトで決まるファイルを作る、新しいスキルを作る

冒頭の表の「対象」に足し、スキルの手順に「規約を見る → 候補を探す → 聞く」を書く。`aidd:adr` の「出力先の決定」が手本になる。

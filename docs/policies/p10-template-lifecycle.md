# P10 雛形は、実物を作ったら削除を提案し、削除は人が行うこと

| 区分 | 内容 |
| --- | --- |
| 対象 | `project:init-repo` が配る `docs/` の雛形（`*.template.*`） |
| 価値 | [V3](../values/v03-human-judgment.md)・[V5](../values/v05-mechanisms-over-habits.md) |

`init-repo` は、`docs/specs/`・`docs/architecture/`・`docs/adr/`・`docs/log/` に、案内板の `README.md` と、実物の雛形（`<実物の名前>.template.<拡張子>`）を置く。雛形から実物を作ったら、Claude は雛形の削除を利用者に提案する。削除は人が行う。

- 雛形の名前は、実物の名前に `.template` を足したものにする（例：`specifications.template.md` → `specifications.md`）。ファイルの名前だけで、実物との対応が分かるようにするため
- 雛形は実物の見本で、`[例: ...]` とガイドのコメントを持つ。実物には、これらを残さない
- 実物を作る手順は、`docs/README.md` の「雛形から実物を作るとき」に 1 か所で書く。雛形の先頭のコメントと `CLAUDE.md` は、そこを指す
- 実物を作ったら、フォルダの `README.md` の一覧を実物の行に差し替える。実物のパスの `@import` は、`CLAUDE.md` の「参照ドキュメント」に先に書いておく。実物が無い間は無視され、できると読み込まれる
- 雛形に、まだ無い実物へのリンクを書かない。利用先で `/aidd:docs-sync` が、壊れたリンクとして数えるため

## 理由

- 【取り違え】雛形を実物と別の名前にしないと、`[例: ...]` が残ったまま、実物として読まれるから
- 【人の判断】雛形を残すか（次の実物の見本にするか）は、人が決めることだから。削除は deny のため、Claude は実行できない（[P1](p01-operation-boundary.md)）
- 【リンク切れ】実物が無い間に、雛形から実物へリンクすると、docs-sync が壊れたリンクとして数えるから
- 【型の統一】どのプロジェクトも、同じ形の文書から書き始めれば、書く場所と見出しがそろうから

## 変えたいとき

- 雛形が要らないリポジトリでは、`init-repo` の引数で、`docs/` の雛形を外して入れる
- 雛形を見本として残したいときは、削除の提案を断る。同じ文書では、同じ提案を繰り返さない

## Q&A

### Q. 実物が無い間の `@import` は、エラーにならないか

ならない。取り込み先が無ければ、黙って無視される。公式の文書には書かれておらず、Claude Code 2.1.310 の `claude -p` で確かめた。挙動が変わったときは、`@import` をコード書式（バッククォート）で囲んで読み込まれないようにし、実物ができたときに足す形に戻す。

### Q. ADR・作業ログのように、何度も作る文書の雛形も、削除を提案する？

最初の 1 件を作ったときに提案する。以後は、直前の ADR・ログを見本にして書く。雛形を残したいときは、利用者が断る。

### Q. `docs/strategies/test-strategy.md` のような骨組みも、雛形にする？

しない。どの利用先にも要る文書は、実物の名前のまま配り、`TODO:` の行を埋めて使う。`.template.` は、プロジェクトによって要らない文書（仕様書・構成図・作業ログなど）に使う。要らない利用先で、実物の名前の文書が中身の無いまま読まれないようにするため。

### Q. 新しい雛形を `init-repo` に足す

名前を `<実物の名前>.template.<拡張子>` にし、先頭のコメントで `docs/README.md` の手順を指す。フォルダの `README.md` の一覧にも載せる。技術に依る雛形は、実際の構成に描き直す前提の見本に限る（[P6](p06-common-template.md) の例外）。

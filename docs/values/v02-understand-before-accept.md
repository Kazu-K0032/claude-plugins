# V2 AI の出力は、実装者が責任を持って品質を確かめてから受け入れること

AI が書いたコードや文書は、処理の流れ・コードの置き場所・使っているライブラリなど、成果物とリポジトリの品質が保たれているかを、実装者が責任を持って確かめてから受け入れる。コードを 1 行ずつ読むことは求めない。どこまで読むかは、チームのレビュー方針に沿って決めてよい。

## 理由

- コードの置き場所が散らばったり、同じ役割のライブラリを二重に持ったりすると、AI がどれに倣うかが定まらず、出力の精度がぶれるから。ぶれた出力の上にさらに出力が重なり、技術的負債が急速に増える
- AI に任せた調査・記述・実装は、もとは理解が貯まる工程だった。品質を確かめずに通すだけでは、自分の中に何も残らないから
- チームごとにレビューの体制が違い、読む範囲を一律には決められないから

## プラグインでの表れ

- `aidd:pr-review` は、レポートを `tmp/` に出すだけで PR に投稿しない。指摘の採否は、人が読んで決める
- `aidd:docs-sync` は、直すべき文書を挙げるだけで、自動では直さない

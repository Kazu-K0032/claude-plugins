# AI駆動開発の価値

このマーケットプレイスが、AI駆動開発で大事にすることをまとめる。[設計の方針](../policies/README.md)は、ここの価値を実現するための決めごと。方針を足すときは、一覧の「読む場面」から価値を探し、どれに基づくかを確かめる。

出典：石井大地『AI駆動開発チームの作り方・育て方』

## 一覧

| 番号 | 価値 | 読む場面 |
| --- | --- | --- |
| [V1](v01-quality-over-speed.md) | 作業時間の短縮ではなく、成果物の質と量を高めること | 早く終わらせる工夫と、確かめる手間のどちらを取るか迷うとき |
| [V2](v02-understand-before-accept.md) | AI の出力は、説明できるまで理解してから受け入れること | AI の出力を、人が読まずに使う手順を作りたくなったとき |
| [V3](v03-human-judgment.md) | 何を作るかと、これで良いかの判断は、人が持つこと | 決める・確定させる操作を、AI に任せてよいか迷うとき |
| [V4](v04-record-reasons.md) | 判断の理由を残し、人と AI があとでたどれるようにすること | 決めたことと、その理由を残すか迷うとき |

## 当てはまらない場面

影響が自分に閉じる個人開発・技術検証・試作は、AI に任せきってよい。速さを優先して結果を作るほうが、得るものが大きいため。

## ファイルの書き方

価値を足すときは、次の形で 1 価値 1 ファイルを作り、上の一覧に行を足す。

```markdown
# V<番号> <価値>

<どうするかを 1〜2 文で>

## 理由

- 【<分類>】<理由>から

## プラグインでの表れ

- <この価値を形にしているスキル・仕組み>
```

- 価値は「〜こと」の形で書く
- ファイル名は `v<2 桁の番号>-<英語の短い名前>.md` にする
- 番号は使い回さない。やめた価値の番号は欠番にする
- 価値と方針の対応は、価値のファイルに書かない。方針の冒頭の表の「価値」の行を正とする（方針から価値を指す、一方向の参照にするため）
- 価値を足す・変えるのは、利用者が決める

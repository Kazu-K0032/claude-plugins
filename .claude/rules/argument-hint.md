# スキルの入力ヒントの書き方

`SKILL.md` の frontmatter の `argument-hint` は、スキルを呼ぶときに入力欄へ表示される。ヒントを見ただけで「何か入力しないといけないのか」「省略したらどうなるのか」が分かるように、書き方を揃える。

## 書き方

| 引数 | 書き方 | 例 |
| --- | --- | --- |
| 任意 | `[何を指定するか（任意。省略時は〜。例: …）]` | `[題材（任意。省略時は対話で補う。例: テスト戦略の採用判断）]` |
| 必須 | `<何を指定するか>` | `<Issue番号>` |
| 動きを切り替える任意の指定 | `[--<英語の名前>（任意。省略時は〜。付けると〜）]` | `[--uninstall（任意。省略時は導入・更新する。付けると外す）]` |
| 受け取らない | `argument-hint` を書かない | なし |

- 任意の引数には、「任意」と省略したときの動き（全部が対象になる・質問される・対話で補う等）を必ず書く。「省略可」などの言い換えは使わない
- `[]` で囲むだけのヒントや、「例:」から始まるヒントは書かない。何かを入力しないといけないように見えるため
- 例は「省略時は〜」の後ろに置く。無くても分かるなら省いてよい
- 一緒に指定する複数の値（開始日と終了日など）は、1 つの `[]` にまとめる
- 動きを切り替える指定は、`--` で始まる英語のオプションにする（[P11](../../docs/policies/p11-options-and-supplements.md)）。Anthropic の公式のプラグイン（`ralph-loop` の `--max-iterations` など）と同じ書き方にし、ほかの引数と見分けやすくするため
- 必須の引数が空で呼ばれたときの動き（質問する等）は、ヒントではなく本文に書く
- 引数を受け取らないスキルは、本文に「引数は受け取らない」と書く

## 任意と必須の分け方

- 任意：省略しても、決まった動き（全部が対象になる・選択肢を出して質問する・対話で補う）でスキルの目的を果たせる
- 必須：指定が無いとスキルの目的を果たせない（調べる内容・対象の Issue 番号など）。空のときに質問して補う作りでも、必須として書く

## 機械チェック

push 前の `/marketplace-update` の機械チェック（`check.py` の `argument-hint`）が、次を検査する。

- 各引数が `[]` か `<>` で囲まれているか（囲みの外に文字が無いか）
- `[]` に「（任意。省略時は」が入っているか
- `<>` に「任意」「省略」が入っていないか
- 本文で `$ARGUMENTS` を使うのに `argument-hint` が無いスキルが無いか（WARN）

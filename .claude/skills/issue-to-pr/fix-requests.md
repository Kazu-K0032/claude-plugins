# 指摘を直す（手順 9）

ワークフローが、CI の失敗やレビューの指摘を渡して直しを頼んだときの手順。直しの回数はワークフローが数え（CI は各段 3 回、レビューは 1 回）、残った指摘は人が判断する。

## 渡されるファイル

ワークフローが prompt で渡したファイルを読み、指摘を直す。ファイルは次のどちらか。

- CI の失敗（`ci-<段>-<回>.log`）：落ちたジョブのログの末尾。原因を直す
- レビューの指摘（`review-feedback.md`）：`/security-review`・code-review の結果と、docs-sync の high・medium。code-review の行ごとの指摘は、ワークフローが取って、同じファイルの「行ごとの指摘」に載せてある（`gh pr view --comments` では読めない）。マージの前に直すべきものだけを直す。直すべきものが無ければ、何も変えずに終わる

## 直した後

- 直したら、`SKILL.md` の手順 5 の検査を流し、手順 6 のとおりコミットして、同じ作業ブランチに push する
- 直したことと検査の結果を、`report.md` の「## 直したこと」に、どのファイルを受けての直しかと一緒に足す
- PR の本文を変えるときは、`gh pr edit <番号> --body-file <本文のファイル>` で直す
- 直さない指摘があれば、理由を「## 直したこと」に書く。残った指摘は、人が判断するため
